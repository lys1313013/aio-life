# AIO Life 接口调用

先按需读取运行时契约，再完成用户要求的查询或操作。默认中文回复。使用可用的 HTTP 工具、curl 或标准库；此 Skill 不依赖专用 MCP，也不自带凭据。

## 服务与凭据

- 默认 API 根地址：`https://aiolife.top/api`。用户指定地址时优先使用，其次读取 `AIO_LIFE_API_BASE_URL`，未设置时使用默认值。
- 本地开发根地址为 `http://localhost:45678/api`，仅在用户要求本地环境时使用。远程 AI 的 localhost 不代表用户电脑。
- 文档匿名可读，读取文档不要携带凭据。受保护业务接口使用运行环境提供的 `AIO_LIFE_API_TOKEN` 或用户指定的安全凭据来源。
- 登录 Token 与 `ak-` 开头的 API Key 均使用 `Authorization: Bearer <凭据>`，不是 `X-API-Key`。
- 凭据仅发送给用户选择的服务，不输出、不写入 Skill、仓库或生成的示例。服务地址变更时不要自动沿用其他环境的凭据。缺少凭据时仍可查文档、准备请求；需要业务数据时说明缺少凭据，让用户在运行环境配置，避免要求其粘贴到聊天。

## 按需发现接口

先判断当前会话是否已经读取过同一服务、同一操作的契约：已确认且无变化迹象时直接调用，只有缺少的契约才重新发现。复用的是接口定义，业务数据每次按用户请求重新查询；切换服务或遇到路由、字段不一致时重新读取。

下面是可选入口，不是每次都要执行的四步流程。已知业务词直接搜索，只有不清楚业务范围时才读目录。

1. `GET {base}/docs/catalog`：读取 `data.modules` 中的模块 `id`、说明及接口数。以实时目录为准，不维护静态接口清单或数量。
2. `GET {base}/docs/operations?keyword=目标&module=record&page=1&pageSize=10`：搜索摘要，读取 `data.items` 中的 `operationId`、名称、方法和路径。
   - `keyword`、`module` 可选；模块取自目录，不确定归属时不传模块。中文参数需 URL 编码。
   - 搜索匹配名称、说明、路径、方法、operationId 和标签；关键词不超过 200 字符。
   - 从用户意图提取关键词，依据返回摘要的业务含义和 HTTP 方法选择必要接口。无相关结果时再调整关键词、尝试同义词或查看目录；不预设业务词到英文路径的固定映射，不把一次部署的搜索表现固化为规则。
   - `page` 从 1 开始，`pageSize` 为 1–100；按需要翻页，空页或达到 `total` 后停止。
3. `GET {base}/docs/operations/{operationId}`：只读取选中接口的详情。`data.definition` 是独立 OpenAPI 文档，包含参数、请求体、响应、鉴权及必要的递归 Schema 引用。operationId 必须来自搜索结果，不能从示例猜测。
4. 依据 `definition.paths`、HTTP 方法、`parameters`、`requestBody`、`responses` 和 `components` 构造请求。解析 `$ref`、必填、枚举及格式，保留循环引用，不无限展开。

仅在用户要求全量导入、全局盘点，或渐进接口不可用时读取模块/完整文档：

- `{base}/v3/api-docs/{group}`：指定模块 JSON。
- `{base}/v3/api-docs`：完整 JSON。
- `{base}/v3/api-docs.yaml/{group}`、`{base}/v3/api-docs.yaml`：对应 YAML。

文档是机器可读 JSON/YAML，不是 Swagger UI。首轮生成索引可能较慢；文档 GET 超时可用较长超时重试一次，持续失败时报告实际错误。若渐进文档返回 404，可尝试完整文档；两者均不可用时说明可能未部署或被 `AIO_LIFE_OPENAPI_ENABLED=false` 关闭，不擅自更改服务器配置。

## 减少调用往返

- 一次批量读取已选中的独立接口详情，不逐条等待模型判断。详情只展示选中 operation 及其引用 Schema，避免重复输出每份文档共有的 `info` 等说明；参数、鉴权、约束和响应结构不能省略。
- 契约确认后，可在一次工具执行中串起有依赖的只读请求：先查列表，再按真实 ID 查询详情。独立详情适度并发（例如最多 4 个），分页遵守当前接口上限。逐个检查 HTTP 和业务状态，某项失败必须保留失败范围，不能当作空数据。
- 优先使用列表中已返回且足以回答问题的字段，仅补查缺少的详情。若契约明确的计数或状态能够排除无关记录，可减少详情请求；字段缺失或含义不明确时不能据此跳过。
- 明确的查询直接执行并返回结果；不要额外调用无关目录、健康检查或未使用的接口。通常使用临时 `curl`／标准库调用即可，无需生成持久脚本，也不把凭据或响应缓存到仓库。

## 请求与结果约定

- 根地址已包含 `/api`，业务 `path` 通常不含；拼接时保留 `/api` 且只出现一次。详情的 `servers[0].url` 通常是 `/api`，以用户选定服务的域名解析相对地址，不把凭据转发到文档中的陌生域名。
- GET 条件平铺，例如 `?page=1&pageSize=50&startDate=2026-09-01`；不发送 GET 请求体，不包装为 `condition`。数组使用重复键，除非当前契约明确规定其他形式。
- ID 和未覆盖序列化器的 Long 响应值是字符串，必须保留精度，不能强转 JavaScript Number。`PageResp.total` 单独按 JSON 整数或 null 读取。日期、时间和枚举遵照具体字段，不统一添加时区或改为时间戳。用户说“今天”等相对日期时，以用户时区计算日期范围。
- 业务后端普通 JSON 响应为 `{ "code": 0, "message": null, "data": ... }`。仅整数 `code == 0` 表示业务成功；HTTP 200 不足以判断。完整 OpenAPI 文档直接返回文档对象，没有业务包装；文件和流式接口按各自媒体类型处理。
- HTTP 401 表示需要有效认证，响应可能是纯文本；403 按实际响应说明权限问题。`code=2001` 表示模块需要二级密码验证，提示用户在应用内解锁 `data.menuPath` 后再继续，不能循环重试或绕过。
- `100400` 是参数错误，`113000` 是通用业务失败；结合 `message` 和契约定位，不把失败包装当作数据。
- 独立 Query 服务的 REST 使用 `rscode/result/data`，GraphQL 和 MCP 也有各自协议；不能套用到本业务后端。
- 业务分页规则以选中接口契约为准，不套用文档搜索规则。汇总只基于实际读取的范围；还有未读取页时说明范围，不能声称已获得全量数据。
- `Object`、`Map<String,Object>`、缺少注释的字段可能没有完整业务语义。必要时查可用源码或询问缺少的具体信息，不能编造字段。调用 `/mcp/tools/call` 前先读取 `/mcp/tools` 的工具 inputSchema。

## 操作范围与验证

查接口、解释文档或生成示例不授权修改业务数据。用户明确要求新增、编辑或删除时，在其授权的对象和范围内执行；已有明确授权不重复索取确认，目标不明确时先查询定位，再澄清有歧义的部分。不可逆或批量破坏性操作应先给出具体对象和影响范围，依照当前会话的授权要求处理。

创建、发送、导入、扣款等可能产生副作用的请求超时后，不盲目重试；先通过查询或接口支持的幂等机制确认结果。仅查询任务不发送消息，不创建测试业务数据。

执行后报告实际结果、对象标识及必要的查询范围。业务写入以成功响应为依据，必要时查询核对；结果不确定时明确说明，不能把请求已发送等同于操作已完成。

## 最小文档查询示例

下面以“目标”为示例，只读取公开文档，不使用 Token；实际关键词按用户意图选择：

```bash
aio_api_base="${AIO_LIFE_API_BASE_URL:-https://aiolife.top/api}"
aio_api_base="${aio_api_base%/}"
curl --fail-with-body --silent --show-error --max-time 45 --get \
  --data-urlencode 'keyword=目标' \
  --data-urlencode 'pageSize=20' \
  "${aio_api_base}/docs/operations"
# 从上述 items 中选择实际 operationId，再请求 /docs/operations/{operationId}。
```
