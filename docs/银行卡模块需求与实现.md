# 银行卡模块需求与实现

## 范围

入口为「财务 → 银行卡」，正式菜单路径 `/finance/bank-cards`。首期实现卡片网格、银行卡新增/编辑/删除、银行/类型/状态/标签筛选、名称和尾号搜索、多标签管理、卡面上传及裁剪、脱敏卡号查看和复制。

信用卡可记录人民币信用额度、每月账单日和固定还款日。不包含余额、交易流水、实际账单、还款记录、自动同步、消息提醒；同银行信用卡可能共享额度，页面不累加信用额度。固定还款日仅是手工记录，不推算真实应还款日期。

银行支持系统字典选择或自定义名称二选一，用户标签复用用户字典；卡面通过文件表反向关联。没有 `bank_name`、`cover_file_id`、`credit_currency` 或标签 JSON 字段。

## 数据结构

完整可执行建表脚本：`../aio-life-server/sql/1_init_table/2026-09-26_add_bank_card.sql`。

- `bank_card.bank_id → sys_dict_data.dict_code`，通过 `sys_dict_data.dict_id → sys_dict_type.dict_id` 确认类型为 `bank`。不能依赖实体中不落库的 `dictType` 属性。
- `bank_card_tag_rel.bank_card_id → bank_card.id`。
- `bank_card_tag_rel.tag_id → user_dict_data.id`，类型为 `bank_card_tag`，标签及关联必须属于银行卡同一用户。
- `file.biz_type='bank_card_cover' AND file.biz_id=bank_card.id` 表示卡面。`file.id` 为 UUID 字符串，银行卡表不存文件 ID。
- 主表及标签关联表采用雪花 ID、逻辑删除和项目审计字段；对外 ID 为字符串。
- `credit_limit DECIMAL(18,2)`：人民币元，NULL 为未记录，0 是明确填写零额度。
- `expiry_month` 存月份第一天；日期输入和展示按年月处理。到期不自动改写正常/冻结/挂失/注销状态。
- `cover_color` 为默认卡面颜色；有上传图片时优先展示图片。`cover_source_url` 仅保存当前图片的出处，不进行远程抓取。

银行卡写操作在事务开始时锁当前用户行；同一用户的卡号判重、标签创建及绑定操作串行执行，支持多实例。逻辑删除后允许重复创建，不添加会阻断多次删除/重建的 `(业务字段,is_deleted)` 唯一索引。

管理员维护银行字典与银行卡保存共享字典类型锁；新建和更换银行要求配置启用，已停用银行的既有卡仍能修改其他字段。已引用银行不能删除或迁移字典类型，银行类型不能删除/改标识。

标签仅通过银行卡模块接口修改；通用用户字典修改入口对 `bank_card_tag` 提示转到银行卡页面，避免绕过一致性规则。标签重命名、改色实时影响引用卡片；删除标签时同步逻辑删除关联。停用标签仍显示已有引用，不接受新增关联。

## 卡号与文件

卡号只接受规范化后的12至19位数字，不用卡号查询外部服务。SM4-GCM 使用随机12字节 nonce、128位认证标签，绑定用户和银行卡 ID 为 AAD；HMAC-SM3 计算按用户隔离的32字节判重指纹。两种用途的子密钥均由同一32字节主密钥通过 HKDF-SM3 派生（SM4子密钥16字节、判重子密钥32字节，使用不同用途标识），无需单独配置判重密钥。普通响应仅包含末四位；完整卡号通过专用接口读取，响应 `Cache-Control: no-store`。银行卡请求体不进入通用参数日志。

页面完整卡号展示15秒后隐藏，切出页面/打开编辑器时清除；复制时重新经过后端权限检查，不保存在 localStorage。银行卡接口、卡面上传、预览和下载接入现有菜单锁。私人卡面要求上传人与访问者一致，即便文件记录误设为公开也不跳过银行卡专用归属检查。

卡面上传支持 PNG/JPEG，最大5MB、1600万像素；前端支持完整显示和居中裁剪，生成960×605 PNG。默认卡面纯代码渲染，暂不内置从银行官网收集的卡面图库。

上传先创建 `biz_id=NULL` 文件。保存时校验文件类型、所属用户和未被其他卡使用，再原子替换。数据库保存失败保留旧卡面；恢复默认/删卡同步逻辑删除对应文件记录。物理对象不在银行卡保存事务中删除，历史文件/浏览器异常关闭留下的临时文件可按存储保留策略另行清理。

## API

统一前缀 `/api`，成功响应 `{ rscode: '0', data: ... }`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/bank-cards` | 当前用户脱敏卡片列表，批量查询字典、标签与卡面 |
| GET | `/bank-cards/{id}` | 当前用户脱敏详情 |
| POST | `/bank-cards` | 新增 |
| PUT | `/bank-cards/{id}` | 全量编辑；卡号留空保留，其他可空字段传 NULL 清空 |
| DELETE | `/bank-cards/{id}` | 逻辑删除卡片、标签关联及卡面 |
| POST | `/bank-cards/{id}/number` | 校验权限后读取完整卡号 |
| GET | `/bank-cards/banks` | 系统银行配置，含启用状态 |
| GET/POST | `/bank-cards/tags` | 标签列表/新建 |
| PUT/DELETE | `/bank-cards/tags/{id}` | 标签修改/删除 |
| POST | `/file/upload` | 复用上传接口，bizType 为 bank_card_cover |

银行卡保存请求的 `tagIds` 是标签 ID 数组；`coverFileIds` 是0或1个文件 ID 的数组，只用于文件表绑定，不存入银行卡表。编辑时须传当前标签/文件列表，空数组表示移除。

## 启用

1. 在目标 MySQL 8 数据库依次执行后端两个脚本：
   - `sql/1_init_table/2026-09-26_add_bank_card.sql`
   - `sql/2_ini_data/2026-09-26_bank_card.sql`
2. 仅配置 `AIO_LIFE_BANK_CARD_ENCRYPTION_KEY`，用 `openssl rand -base64 32` 生成一次，作为32字节Base64主密钥。应用不提供默认密钥。密钥需安全备份，存放位置与数据库备份隔离；不再读取或需要 `AIO_LIFE_BANK_CARD_FINGERPRINT_KEY`。
3. 重启使用新代码的后端，部署新前端；重新登录/刷新菜单以读取银行卡入口。

Compose 已通过 `env_file: .env` 传入配置，示例见根目录 `.env.example`。本地 Java 启动需要将变量显式放入进程环境或 IDE 启动配置，单纯创建 `.env` 不会自动注入 Java。

不要直接替换已使用的主密钥：已有卡号读取和判重均依赖它。新写入密文版本为 `v2:nonceBase64:ciphertextAndTagBase64`（SM4-GCM）；未实现主密钥轮换。

银行字典以金融监管总局截至2025年末的法人名录为底库，覆盖3132家大陆银行/农信机构（含初始15家），来源、筛选范围和接口调研见后端 `sql/reference/banks/README.md`。这不是所有卡种或发卡资格清单，也不涵盖港澳台本地银行及历史撤并品牌。脚本保留已有ID和人工修改；主键冲突直接失败，不会静默覆盖。管理员仍可在系统字典维护补充项。

## 自定义银行名称

银行输入框支持下拉选择和直接输入。选中系统银行时传 `bankId`，`customBankName=null`；手填时传 `bankId=null`，`customBankName` 为去除两端空白后的银行名称（1至100个字符）。二者不能同时填写或同时为空，后端与数据库 CHECK 均约束数据来源。

初始建表脚本已包含 `bank_card.custom_bank_name VARCHAR(100) NULL`，`bank_id` 可空，无需单独执行自定义银行的 ALTER 脚本。自定义名称仅属于当前用户的这张卡，不写入公共系统字典。切换回系统银行会清空自定义名称；切换为自定义会清空字典ID。原银行卡关联不变。返回的 `bankName` 统一用于展示；自定义银行的 `bankCode` 为空。搜索和银行筛选均支持自定义名称。

自定义银行的改名只影响当前卡，不自动修改其他同名卡，也不会在管理员补入同名系统银行后自动更换关联。用户可编辑卡片、选中对应系统银行完成关联。

本次自定义银行变更验证：银行卡后端11项测试、前端筛选4项测试、类型检查及限定文件ESLint通过；模拟接口浏览器验证新增、改名、双向切换、搜索，以及390/768/1440宽度和暗色输入建议。未执行目标数据库迁移或服务部署。

## SM4加密实现

本次仅调整银行卡模块，通知配置和密码本实现保持各自当前行为。Java显式声明项目运行时已有的 `bcprov-jdk18on:1.81`，使用局部 Provider 实例，不改变 JVM 全局 Provider 顺序。SM4-GCM与HKDF采用库实现，参考 [SM4-GCM文档](https://downloads.bouncycastle.org/java/docs/bcprov-jdk18on-javadoc/org/bouncycastle/jcajce/provider/symmetric/SM4.GCM.html) 和 [HKDF文档](https://downloads.bouncycastle.org/java/docs/bcprov-jdk18on-javadoc/org/bouncycastle/crypto/generators/HKDFBytesGenerator.html)。

- 只配置一个32字节Base64主密钥，所有新卡号密文均为SM4-GCM，判重使用HMAC-SM3。原表字段长度足够，无需新增迁移脚本。
- `v2`的用途标识为 `aio-life/bank-card/v2/sm4-gcm` 与 `aio-life/bank-card/v2/fingerprint`，HKDF不另设配置盐。修改这些标识会改变子密钥，必须作为新版本迁移，不能直接替换。


本模块确认无历史数据，仅实现SM4-GCM读写，不保留AES解密、旧数据扫描、指纹迁移或自动升级逻辑。非当前格式的密文直接拒绝。
