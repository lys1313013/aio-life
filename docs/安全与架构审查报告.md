## 一、安全风险

### 严重（Critical）

| # | 位置 | 问题 |
|---|------|------|
| S1 | `aio-life-serve/src/main/resources/application.yml:105` | **JWT 密钥硬编码且极弱**：`jwt-secret-key: lys` 已提交进仓库。任何人拿到该值即可伪造任意用户的 Sa-Token JWT，完全接管账户。需改为环境变量注入并**立即轮换**。 |

### 高（High）

| # | 位置 | 问题 |
|---|------|------|
| H1 | `config/CorsConfig.java:16-27` | **CORS 危险组合**：`allowCredentials(true)` + `allowedOriginPatterns("*")` + `allowedHeaders("*")`，任意网站可携带用户凭证跨域调用 API。应改为明确的前端域名白名单。 |
| H2 | `sso/service/impl/UserServiceImpl.java:88,96` | **登录日志明文记录密码**：登录失败时把用户输入的明文密码写入 `login_log` 表（用户可能只是打错一位真实密码）。应删除 `setPassword(...)`。 |
| H3 | `sso/api/FileController.java:33` + `SaTokenConfig.java:84` | **未鉴权的任意 MinIO 对象读取**：`/file/preview/{*fileName}` 被排除鉴权，桶名、对象名完全由路径控制，可读 MinIO 实例中任意桶的任意对象。应限定桶名并校验归属。 |
| H4 | `aio-life-front/apps/web-antd/src/views/message/index.vue:786,583` | **AI 聊天 Markdown 渲染无消毒（XSS）**：`v-html="renderMarkdown(...)"`，`renderMarkdown` 直接调 `marked.parse()`，全仓库无 DOMPurify。AI 返回内容含恶意 payload 可直接执行，窃取 localStorage 中的 token。 |
| H5 | `aio-life-front/apps/web-antd/src/views/_core/profile/mbti-setting.vue:394` | **MBTI 匹配结果 `v-html` 渲染 LLM 内容**：LLM 输出属不可信输入，构成存储型 XSS。 |
| H6 | `aio-life-front/apps/web-antd/src/utils/crypto.ts:60-66` + `PasswordModal.vue:171` | **AES-GCM 随机数（nonce）复用**：IV 取 `salt.slice(0,16)`，salt 仅新建时生成，编辑已有记录时 key 和 IV 均不变。GCM 同 key 同 nonce 重复加密会泄露认证密钥并允许密文伪造，属密码学严重缺陷。应每次加密生成独立随机 IV 随密文存储。 |

### 中（Medium）

| # | 位置 | 问题 |
|---|------|------|
| M1 | `UserServiceImpl.java:389-394` | 邮箱验证码（6 位数字，5 分钟有效）校验**无失败次数限制**，可在线爆破；且使用 hutool `RandomUtil.randomNumbers`（非 CSPRNG）。应加错误次数上限并改用 `SecureRandom`。 |

## 二、架构与设计问题

### 架构级

| 级别 | 位置 | 问题与影响 |
|------|------|-----------|
| 必须改 | `record/api/` 下 20+ Controller（`IncomeController`、`TaskController` 等） | **Controller 绕过 Service 直操作 Mapper**：Controller 内拼 `LambdaQueryWrapper`、做增删改查、直接把 Entity 返回前端，分层名存实亡；业务规则无法复用，实体变更直接击穿 API，事务边界缺失。CRUD 应下沉到 Service，返回 VO。 |
| 必须改 | `record/autotask/AutoTask.java`、`sso/autotask/UserLastActiveSyncTask.java` | **定时任务无分布式锁**：`@Scheduled` 裸用，多实例部署时 LeetCode 打卡检查、邮件通知会重复执行（重复发邮件）。应用 Redis `SETNX` 或 ShedLock。 |
| 建议改 | `record/service/impl/LeetcodeServiceImpl.java` 等 3 处 | **跨模块通过 Mapper 耦合**：record 直接 import sso 的 `UserMapper` 查库，模块边界靠自觉。跨模块应只走对方 Service 接口。 |
| 建议改 | 15 个 Controller | RESTful 名不副实：大量 `POST /insertOrUpdate`、`POST /delete`、`POST /query` RPC 风格，与项目自述约定矛盾。 |
