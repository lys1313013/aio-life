# 首页卡片功能与跨端交互

本文是 Web、Mobile H5、微信与 App 首页的共同需求入口，维护卡片范围、刷新语义及操作规则。实现差异和证据见 [首页卡片核查与补齐清单](mobile-migration/home-card-audit.md)；需求实现与平台验证分别记录。

`overview.read` / `section.weread` 使用微信读书数据，`section.reading` 使用用户维护的阅读记录，不能混为一张卡片。兼容历史概览类型也应依据实际 `/dashboard/tasks` 返回值处理。

- `GET /home/cards` 获取设置；`PUT /home/cards/{cardKey}` 保存 `{ isEnabled: 0 | 1 }（1 启用、0 停用）`；`PUT /home/cards/order` 保存 `{ group, keys: string[] }`；`DELETE /home/cards` 恢复默认，写入返回更新后的完整设置。
- 概览与内容分组分别排序，不跨组移动。排序提交该组完整集合，关闭或因空数据隐藏的卡片也保留配置，不因可见集合变化丢失它们。
- 用户可从首页卡片设置启停、排序和恢复默认；首页长按约 300ms 后拖动排序，普通滑动继续滚动，取消或拖动结束不得误触刷新、跳转或编辑。保存失败恢复原顺序。
- 设置保存在服务端，跨端读取同一份；启用设置不授予业务权限，也不能绕过二级锁。关闭的卡片不发业务请求。
- 图标与颜色遵守 [图标与颜色统一规则](图标与颜色统一规则.md)，统一引用对应菜单配置。
- 新增卡片默认展示，便于用户发现新功能；最近笔记、收支概览、收入、支出、视频续看、我的设备均默认开启，恢复默认也开启。已保存的用户开关设置优先保留；仍遵守业务权限与二级锁。

## 刷新规则

两端按以下规则刷新。Mobile 的周期调度与顶部空白刷新实现见核查清单中的修复记录。

### 刷新方式与作用范围

| 触发 | 行为 |
| --- | --- |
| 首次进入 | 先加载设置、权限等依赖，再并行加载启用且有权限的区域；单卡失败不阻塞其他卡片 |
| 概览卡片普通点击 | 仅刷新这张概览；图标／标题配置了跳转或快捷动作时执行该动作，无动作时可刷新本卡 |
| 内容卡片顶部空白点击 | 仅刷新本卡；标题跳转、加号、条目编辑、复选框、排序操作均不触发刷新 |
| 微信读书卡片空白点击 | 刷新最近阅读；标题进入微信读书，书籍点击打开阅读链接，互不触发刷新 |
| Mobile 整页下拉 | 强制更新首页依赖与各启用区域；最后结束下拉状态，包括失败场景 |
| 前台定时刷新 | 按下表独立更新到期区域，保留已有内容；请求中不重复查询同一区域 |
| 本端写入成功 | 更新受影响条目或将相关区域标为失效，必要时仅重新查询该区域 |
| 返回首页／恢复前台 | 检查权限、二级锁、失败、写入失效与数据时效；补刷需要更新的区域，恢复刷新调度 |

Mobile 的整页刷新继续使用下拉，不增加导航栏或卡片常驻刷新图标；单卡顶部空白刷新是补充的局部入口，两者可以并存。失败时允许显式局部重试。快捷导航两端均支持顶部空白刷新，编辑或保存草稿期间禁止刷新覆盖草稿。空白刷新入口须有可访问名称；H5 / Web 支持键盘触发，触摸平台保留足够的点击范围。

### 自动刷新间隔

概览详情 `GET /dashboard/card/{type}` 返回 `refreshInterval: number`，单位为**秒**。Web 与 Mobile 均读取这个字段建立单卡调度。当前服务端默认 600 秒，今日阅读显式设置为 300 秒，最终以每次接口响应为准。缺失、无效或非正值时不创建自动刷新定时器，仍保留手动刷新与错误重试。

| 内容区域 | 前台刷新周期 | 依据与边界 |
| --- | --- | --- |
| 今日时迹 | 300 秒 | 当前 Web `SECTION_REFRESH.timeTracker` |
| 运动汇总 | 600 秒 | 当前 Web `SECTION_REFRESH.exercise` |
| 关注待办 | 1800 秒 | 当前 Web `SECTION_REFRESH.watchedTasks` |
| 固定闪念 | 3600 秒 | 当前 Web `SECTION_REFRESH.thoughts` |
| GitHub 最近提交 | 3600 秒 | 当前 Web `SECTION_REFRESH.github`；仅已绑定且启用时查询 |
| 最近笔记、收支概览、收入、支出、视频续看 | 接口当前为 300 秒 | 读取对应 `/home/sections/` 摘要接口的 `refreshInterval`，单位秒 |
| 我的设备 | 接口当前为 600 秒 | 读取 `/home/sections/device` 的 `refreshInterval`，单位秒 |
| 快捷导航、目标、纪念日、阅读、会员、观影、微信读书最近阅读 | 暂无共同定时周期 | 依靠首次加载、手动刷新、写入失效、返回时效检查；不能把这些卡片记为已有周期刷新 |

- 离开首页、应用后台或组件卸载时停止请求调度，使旧响应失效；恢复后只保留一套定时器。H5 浏览器隐藏也应停止请求，不能仅检查首页 tab 是否选中。
- Mobile 首页依赖与五张业务卡片的 60 分钟时效，是页面激活时检查的内存数据时效；概览与五类内容区另外按各自周期调度，到期返回只补刷对应区域；微信读书最近阅读使用 5 分钟时效。**时效检查不等于持续停留时自动刷新**，也不等于展示时长每分钟变化。
- 展示“距上次记录时长”只需每分钟更新本地时间；跨日须重新查询当天时迹，不能沿用昨天的记录。这个时钟不能代替 300 秒的数据刷新。
- 定时刷新只查询数据，不主动触发第三方同步、写入或密码解锁弹窗。锁过期后清除受保护旧内容，并提供用户主动解锁入口。

### 请求、错误和分页

- 首次加载按卡片真实结构显示骨架；已有内容（包括空结果）刷新时保持内容与高度，反馈不参与布局。具体遵守根项目及两端 AGENTS.md 的 Loading 高度规范。
- 请求失败不能当成空数据隐藏；首次失败显示卡内重试，已有内容失败保留内容并提供局部重试。首次失败尚未取得 `refreshInterval` 时，返回前台也可重试恢复。
- 同区域请求去重；写入后的更新使写入前查询失效。刷新、离页、切换账号及权限变化后的旧响应不得覆盖新状态，也不得结束新请求的 loading。
- 滚动到内容底部自动分页；失败保留列表与已成功页码，重试失败页。末页、空页停止，去重保留字符串 ID。刷新使旧分页响应失效；普通短时间返回保留已加载分页。
- 仅凭 HTTP 200 不能认为成功，按 `{ code: 0, message: null, data: ... }` 处理。ID 全程为 string；计数按实际 JSON 契约处理。

## 各卡片业务操作

| 卡片 | 数据与操作 |
| --- | --- |
| 概览 | 任务列表决定可用类型，详情决定数据、颜色、图标／标题链接和刷新间隔。时迹快捷动作打开共用记录弹窗，运动标题进入运动业务页；长按用于排序，快捷录入使用明确点击入口 |
| 今日时迹 | 时间轴、环图、当日全部明细，按开始分钟倒序，首屏紧凑显示约五行，其余内部滚动；点击记录编辑，右上“距上次记录时长 ＋”新增。无记录仍保留录入入口。详见 [今日时迹卡片设计](今日时迹卡片设计.md) |
| 快捷导航 | 使用用户常用菜单，点击进入授权业务，设置入口管理快捷项。数据与客户端适配见 [需求方案](首页快捷导航-需求方案.md)、[技术方案](首页快捷导航-技术方案.md) |
| 关注待办 | 展示优先级、内容、主任务名和起止时间；点复选框标记完成，成功后就地显示勾选与删除线，保留原位置直到下一次手动或自动刷新才移除，刷新前可取消勾选；点内容在首页编辑。刷新成功且列表为空时隐藏；失败可重试，完成请求按条目反馈 |
| 固定闪念 | 展示固定内容与日期，隐藏正文的记录不泄漏原文；点击条目在首页编辑，右上新增。空结果保留现有空态 |
| 运动汇总 | 按日期、类型展示次数、变化和近期趋势，卡内分页；标题进入运动页，右上新增运动；保存后更新汇总及相关概览。空结果隐藏 |
| GitHub 最近提交 | 已绑定时展示仓库、提交摘要和日期，卡内分页；保留个人主页与单次提交的访问入口，触摸端不能只依赖悬停查看长摘要 |
| 目标、纪念日、阅读、会员、观影 | 条目编辑、新增、取消固定、顺序及状态筛选见 [首页新增业务卡片需求](首页新增业务卡片需求.md)。标题进入业务列表，点击条目在首页使用共用编辑器；按菜单与锁控制数据读取，成功空结果隐藏 |
| 微信读书最近阅读 | 绑定后展示封面、书名、作者、进度和阅读时间；按 cursor 分页，未连接隐藏。点击书籍打开对应阅读链接，平台无法打开时提供可用回退；与手动阅读记录分开 |
| 最近笔记 | 按最近修改时间展示三篇笔记的标题与修改时间，卡片接口不返回正文。点击条目读取完整记录后查看或编辑，不能把摘要或缺失正文当作完整内容保存。不增加固定笔记能力 |
| 收支概览 | 展示所选范围的收入、支出、结余，使用与收支卡片共用的周／月／年日历。三项合计可切换格子指标，默认结余；点击格子打开可切收入／支出的明细弹窗。无账目显示零值，查询失败保留原内容并重试；同时遵守财务概览、收入和支出的权限与二级锁 |
| 收入 | 展示所选范围总额与周／月／年金额格子（不提供日），与支出复用卡片和明细弹窗；标题进入收入列表，不显示新增入口，只依赖收入业务权限与二级锁 |
| 支出 | 展示所选范围的总额与金额日历，按日、周、月、年查看；标题进入支出列表，卡片不显示新增入口，只依赖支出业务权限与二级锁。Web 与 Mobile 使用相同交互契约，各端内部复用收支组件 |
| 视频续看 | 展示最近观看的三条进行中视频，显示视频封面、标题、当前集数与进度，点击继续观看；已完成、暂停和未开始的视频不混入续看列表。外链沿用各平台可用的打开或复制方式 |
| 我的设备 | 按购买日期倒序展示三台在用设备的图片、名称、使用天数与日均费用；日均费用沿用购买价除以使用天数的口径，有购买日期时使用天数最少一天，缺失数据不伪装为零费用。点击条目直接在首页打开设备编辑弹窗，关闭后仍停留首页；保存或删除后刷新本卡 |

Mobile 普通标题使用独立业务入口；待办显示起止时间；GitHub 标题访问公开绑定的个人主页，点击提交可查看完整摘要并访问提交。H5 新窗口、微信复制链接、App 外部打开分别适配，平台实测边界见核查清单。

最近笔记、视频续看、我的设备是有界摘要，点击标题进入业务页查看完整列表，摘要不另做分页。摘要卡共用加载、错误重试、请求去重和生命周期处理；业务筛选、排序、收支统计和设备费用由服务端统一提供。

### 财务统计范围与图片

- 收支概览与收入均使用“周／月／年”，默认周；结余为收入减支出，年视图覆盖本人全部未删除账目。概览首页卡片和独立概览页面复用相同组件与接口，页面保留收入／支出业务导航及记账入口。
- 收支卡片标题行右侧切换粒度：支出“日／周／月／年”，默认日；收入“周／月／年”，默认周。粒度按业务和当前账号分别保存在客户端本地，刷新后恢复；收入和概览遇到旧的日粒度自动回退周。左侧在日、周视图选择月份，在月视图选择年份，年视图隐藏时间选择。时间文字旁不展示下拉三角，保留左右箭头与点击选择；日期不附加圆点。日期游标仅保留在本次页面浏览中，重新打开按当前月／年展示。总额以普通字重显示在时间选择行右侧，日历使用小字号与紧凑行高；Web 卡片与其他摘要卡片对齐（中屏 250px、桌面 280px），日视图各行按可用高度均分，六行月份完整展示；周、月视图按可用高度展开；年视图使用正常行高并靠上排列，剩余区域留白，不拉伸格子；切换时间、粒度及刷新时，在日历区域叠加转圈 loading，保留原内容和高度，失败时原位重试。
- 日视图为周一开始的金额日历；周视图按周一至周日汇总，跨月周只计算所选月内部分，合计与日视图一致。月视图显示所选年的十二个月；年视图显示全部有账目年份，历史未填日期账目单列“未填日期”，不从全部合计中丢弃。无账目月份保留零值日历；已有未来日期账目仍显示其金额。大额数字不附带“本月累计支出”等副标题或“元”。点击格子打开居中的对应收支明细弹窗，按该格子的起止日期分页查询实际账目，展示交易描述、交易对方、时间、分类、支付方式、记账金额和备注，交易号等信息按需展开；收入展示日期、分类、备注、金额与税额。Web 使用分页，Mobile 在弹窗内触底自动加载，分页失败保留已有列表并重试失败页；卡片底部不再追加选中金额。点击账目主体打开居中的编辑弹窗，复用对应收入／支出列表的表单；交易信息展开不触发编辑。编辑已有账目时，弹窗底部左侧显示垃圾桶，点击后在按钮旁提示“确认删除？”。删除成功关闭编辑弹窗并更新原范围明细、合计和首页卡片；删除失败保留弹窗并允许重试。取消或保存失败保留原明细，失败保留表单供重试；保存成功按原范围更新明细、明细合计、对应业务卡片与收支概览，修改日期移出范围的记录不再显示，Web 末页变空时回退到有数据的页。弹窗支持局部 loading、空态、失败重试和关闭，翻页失败保留已有列表，关闭或切换账号后丢弃旧响应。未填日期格子仅查询无日期账目。
- 支出日历使用 `/home/sections/expense/calendar?granularity=day/week/month/year`；日、周附 `date=yyyy-MM`，月附 `date=yyyy`，年不附日期。服务端返回完整格子、范围及精确合计，按本人未删除账目聚合。收入使用 `/home/sections/income/calendar?granularity=week/month/year`，日期规则相同，服务端拒绝收入日视图；收支复用聚合分桶逻辑和返回模型。概览使用 `/home/sections/finance/calendar`，与收入相同粒度，顶层和每格返回 `income/expense/balance`，`amount` 为结余；同一只读事务内查询收支，合并不同年份与未填日期。概览明细按当前指标默认收入或支出（结余默认支出），可在弹窗切换，合计取对应类型而非结余。明细使用对应 `/expense/query` 或 `/income/query`，通过 `startTime`（含）、`endTimeBefore`（不含）筛选；收入日期使用 `yyyy-MM-dd`，支出使用 `yyyy-MM-dd HH:mm:ss`；无日期使用 `undated=true`。旧三类摘要接口已移除，客户端统一使用上述日历接口。
- 切换只刷新当前卡片，保留已有内容及高度并显示局部 loading；不能把旧范围的金额标成新范围。快速切换、失败重试和返回首页时，旧响应不能覆盖当前范围。已选本年不因跨月误刷新为本月，全部也不被自动重置。
- 记收入成功后使收入与收支概览失效，记支出成功后使支出与收支概览失效；重新查询继续使用各卡当前范围。
- 设备图片和视频封面沿用业务的鉴权文件链路，封面不直接改用外部图片地址。缩略图使用固定占位尺寸，加载中、无图片、加载失败时不改变行高；图片错误不阻塞金额、标题和其他操作。
