# 图标与颜色统一规则

同一业务在菜单、首页卡片、首页卡片设置和快捷导航中，必须引用同一份图标与颜色配置。修改对应菜单的图标或颜色后，所有引用位置随菜单配置刷新同步更新，不再分别维护。

本文覆盖 Web、移动端及微信小程序，作为实现与验收依据。业务身份图标与颜色已按下述公共引用链改造；实际验证范围见文末。

## 唯一配置来源

| 展示对象 | 唯一来源 | 引用规则 |
| --- | --- | --- |
| 有对应菜单的业务标识 | 对应业务菜单配置 | 图标与颜色一起引用，不在卡片、页面或设置项中另配一份 |
| 无对应菜单的公共功能，如快捷导航容器 | 集中维护的公共视觉配置 | 所有使用位置引用同一条配置；以后关联菜单时改为引用菜单 |
| 新增、编辑、删除、刷新、拖动等通用操作 | 公共操作图标及主题语义颜色 | 同一操作使用同一规则，不借用业务菜单颜色 |
| 分类、单条记录和品牌标识 | 对应分类、记录或品牌的配置 | 在同一对象的不同展示位置复用其配置，不替换成模块菜单图标 |

菜单配置沿用现有字段：数据库 `sys_menu.meta.icon` 保存图标，`sys_menu.icon_color` 保存颜色；菜单接口对应 `meta.icon` 和顶层 `iconColor`。业务展示不得新增一套平行的图标、颜色字段作为独立配置来源。

接口可以返回从菜单解析得到的展示结果，但该结果是派生值。首页卡片偏好只管理显示、顺序等偏好，不保存独立的图标与颜色快照。

## 同一业务的展示范围

以下位置展示同一业务身份时，图标形状和图标颜色必须一致：

- 菜单入口，包括侧栏、移动端生活菜单等入口。
- 首页概览卡片和详情卡片的业务图标。
- 首页卡片设置中的对应行。
- 快捷导航中的业务入口。
- 业务页面标题及其他表示该业务身份的入口。

图标尺寸可随位置调整，但不能换用另一套图标、描边或填充形式。标题文字默认沿用统一文本样式，不要求整段文字染成业务色；若展示业务色背景、边框或标签，其颜色必须由同一业务颜色通过公共规则派生，禁止另写近似色。

卡片里的内容图标按对象身份区分。例如，运动卡片标题引用运动菜单；跑步条目的图标和颜色引用跑步分类。纪念日标题引用纪念日菜单，某条纪念日自己的图标仍引用该记录配置。

## 业务关联规则

以稳定的业务标识关联对应菜单，不能按显示名称、翻译文字或图标名称猜测业务。一个业务可对应多个展示项，这些展示项引用同一个菜单。

建议在公共目录中集中维护“业务标识 → 对应菜单”的关联，由服务端提供一致的关联结果，Web 和移动端各通过公共解析层消费。菜单 ID 全程按字符串处理。现有路由名称或路径可用于兼容关联，但兼容别名只能集中登记，不能在各组件中重复维护。

首页现有卡片的关联按实际业务确定：

| 卡片标识 | 展示名称 | 配置来源 |
| --- | --- | --- |
| `section.time` | 时迹 | 时迹记录菜单 |
| `section.watched` | 待办 | 待办菜单 |
| `section.thoughts` | 闪念 | 闪念菜单 |
| `section.goal` | 目标 | 目标菜单 |
| `section.anniversary` | 纪念日 | 纪念日菜单 |
| `section.reading` | 阅读 | 阅读记录菜单 |
| `section.membership` | 会员 | 会员菜单 |
| `section.movie` | 观影 | 观影记录菜单 |
| `overview.exercise`、`section.exercise` | 今日运动、运动 | 运动记录菜单 |
| `overview.github`、`section.github` | GitHub、GitHub 最近提交 | GitHub 菜单 |
| `overview.leetcode` | 每日一题 | LeetCode 菜单 |

| `section.links` | 快捷导航 | 公共快捷导航配置；其中每个业务入口分别引用自己的菜单 |

关联的是业务身份，不是点击目的地。外部链接、弹窗动作和无跳转卡片也按实际业务关联配置；统一图标与颜色不改变原有点击行为。

## 颜色规则

1. **业务图标颜色直接引用菜单 `iconColor`。** 配置了颜色时，设置列表、菜单、卡片标题和快捷导航不得各自覆盖为白色、灰色或主题主色。
2. **颜色允许不配置。** 未配置时，各位置使用统一的默认图标颜色令牌，不随机分配颜色，也不回退到组件自己的业务色。
3. **配置颜色统一使用 `#RRGGBB`。** 空值表示默认颜色；非法值按统一校验和回退规则处理，不由各页面分别解释。
4. **深浅主题使用同一套解析规则。** 默认图标色随主题变化；有效的菜单颜色默认保持原值。如果需要主题适配，必须在公共解析层处理，确保同一业务在同一主题下得到相同颜色，不能在单个页面自行提亮、变灰或反色。
5. **业务色和状态色各有来源。** 成功、警告、错误、禁用、选中以及加载反馈使用公共语义颜色令牌；所有业务中的同一种状态遵循同一规则。删除按钮使用危险色，开关使用公共控件色，不随所属业务变色。
6. **业务色派生样式统一计算。** 确需浅背景、边框或透明效果时，由公共规则派生，禁止复制颜色再手工调整。
7. **品牌图像遵循同一资产规则。** 多色品牌图像保留原色，不强制套用单色 `iconColor`；同一品牌在不同位置必须使用同一资产及着色规则。主题专用资产也由公共层选择。

“颜色统一”指来源和语义统一：同一业务标识同色、同一种状态同色、同一种操作同色。无需把业务标题、错误提示、正文和按钮全部改为一种颜色。

## 公共引用与降级规则

每端使用一个公共业务视觉解析入口，根据业务标识返回同一组图标、颜色和来源。各页面只传业务标识与尺寸等展示参数，不传自己的备用业务图标或颜色。

解析按以下规则执行：

| 情况 | 展示规则 |
| --- | --- |
| 找到菜单且图标有效 | 使用该菜单图标；颜色使用菜单颜色或公共默认色 |
| 菜单图标为空或客户端缺少该资产 | 使用公共缺省图标；不能由各组件挑选不同备用图标 |
| 已明确属于无菜单公共功能 | 使用对应的公共视觉配置 |
| 业务应有关联菜单，但关联失败 | 使用统一缺省展示，并记录可排查的配置缺失；不能悄悄创建第二份业务配置 |
| 菜单配置首次加载中 | 使用统一占位或缺省展示，预留相同图标尺寸 |
| 菜单配置刷新中或刷新失败 | 同一用户下保留最后一次成功配置，失败可重试；不切换到另一套业务外观 |

图标和颜色按同一版本一起更新，不能一处已更新、一处仍保留旧副本。菜单刷新完成后，已经打开的页面和设置列表也应响应更新。当前要求不包含跨设备实时推送；其他会话在下次菜单刷新或重新登录后获取新配置。

退出登录、切换账号时清理该用户的菜单及派生缓存，旧请求不得覆盖新用户配置。菜单缺失、隐藏、无权限与二级锁仍沿用各自规则；图标解析不能补出入口或授予业务访问权限。

首页卡片恢复默认只恢复卡片偏好，不能把图标或颜色恢复成卡片目录中的旧值。拖动排序、开关显示和业务数据刷新也不能改变视觉配置来源。

## 本地图标资产规则

菜单配置负责决定使用哪个图标，客户端图标目录负责提供对应资产。图标目录是资源集合，不是第二份业务配置。

- Web 和移动端的同一完整图标标识必须对应同一图形，禁止移动端自行映射为“相似图标”。
- 新菜单图标必须进入本地支持目录；不能依赖移动端运行时请求外部 Iconify 服务补齐。
- Web 资产通过 `pnpm icons:generate` 生成，并用 `pnpm icons:check` 检查。
- 移动端资产通过 `npm run icons:sync` 同步，并用 `npm run icons:check` 检查；不得手工编辑生成文件。
- 已包含的资产可随菜单配置刷新切换。新增未打包资产还需要客户端重新构建与发布，不能把服务端改配置视为已发布客户端支持了新图标。

## 实现入口

业务与菜单的关联集中在服务端 `MenuVisualService`。`HomeCardCatalog` 只登记卡片标识、业务视觉标识及默认偏好，不再为业务卡片定义独立图标。

`GET /menu/visuals?client=web` 或 `client=mobile` 使用当前登录用户的角色与对应客户端授权菜单树，返回 `menus` 和 `cards` 两部分。`menus` 提供菜单 ID、路径、图标与颜色，`cards` 按稳定卡片标识引用对应菜单的同组视觉数据。菜单 ID 使用字符串，无菜单公共功能和缺省图标也在服务端集中定义。

| 位置 | 公共引用方式 |
| --- | --- |
| 菜单路由及快捷导航候选 | `MenuServiceImpl` 使用公共规则规范图标与颜色，管理端编辑数据保留原始配置 |
| 首页卡片偏好接口 | `HomeCardPreferenceService` 从同一菜单视觉服务派生 `icon` 与 `iconColor`，不写入偏好表 |
| 首页概览接口 | `DashboardController` 统一解析菜单视觉；各 Provider 只提供业务数据与交互目的地 |
| Web 首页与设置 | `useMenuVisualsStore` 共享快照，`BusinessIcon` 统一渲染；业务卡片按服务端返回的菜单 ID 查找权限链，不再维护自己的菜单路径关联表 |
| Web 导航刷新 | 按同一授权菜单快照同步菜单、快捷入口及卡片视觉，避免分别刷新留下旧颜色或旧图标 |
| 移动端首页与设置 | `menuVisuals` 共享响应式快照，`BusinessIcon`、`LifeMenuIcon` 和 `DashboardSection` 复用其结果 |
| 移动端生活菜单及快捷导航 | 按菜单 ID 读取同一快照，不再按标题猜图标或在页面中覆盖为灰色 |
| 移动端菜单配置写入 | 成功后自动刷新公共视觉快照，更新当前已经打开的展示位置 |

Web 在导航刷新时更新配置；移动端配置最多复用 60 秒，首页刷新可主动重新获取。两端均保留最近成功快照，切换用户时清理，丢弃过期请求的响应。

移动端品牌图标使用从 Web 同步的 SVG 资产，复用原始图形及配色；不再在不同展示位置另选 PNG。新菜单图标进入 Web 本地支持配置后，通过生成与同步命令进入两端产物。

## 验收规则

- 修改时迹、阅读或观影菜单图标与颜色，刷新菜单后，菜单入口、首页卡片、首页设置项和快捷导航同时采用新配置。
- 菜单名称修改、卡片标题改名或拖动排序后，业务关联不变；今日阅读仍关联微信读书，普通阅读仍关联阅读记录。
- 清空菜单颜色后，所有对应位置使用同一主题默认图标色，不残留组件自带颜色。
- 手机、平板、桌面及深浅主题下，同一业务的图标形状与解析颜色一致，尺寸可以不同；品牌图像保持统一资产规则。
- 缺少图标、首次加载、刷新失败和重试时遵循公共降级规则；加载切换不改变图标占位和后续内容位置。
- 切换账号后不残留上一用户配置，旧响应不能覆盖当前配置；隐藏、权限和二级锁行为不受影响。
- 恢复首页默认设置、切换开关、调整顺序和刷新业务数据，都不回退或重写菜单视觉配置。
- 业务身份图标与操作、状态、记录图标各自使用正确来源；成功、错误、禁用等语义颜色在各业务间一致。
- 新图标在 Web、移动端本地资产检查中通过，并分别报告构建、上传或发布的实际验证状态。
- 源码检查确认各消费位置不再独立维护同一业务的图标、颜色或备用值；验证包含真实配置变更后的展示结果，而不只比较固定字符串。
