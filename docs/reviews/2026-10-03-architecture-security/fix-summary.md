保持 Server 单体、Front Vben 与 Mobile Vapor 架构。用户本次选择的 10 项架构/功能问题已完成代码及相应验证；没有为此拆服务或整体更换框架。完整任务清单见 [fix-tasks.md](fix-tasks.md)。

## 已修复

| 范围 | 结果 | 说明 |
| --- | --- | --- |
| Server S1 | 菜单/二级锁直接读取数据库权威配置 | 专用 Mapper 不复用 MyBatis 授权缓存；取消依赖提交后 Redis 失效，代价是每次读取小配置的数据库查询 |
| Server S2 | 上传/删除使用相同 bucket/key 对象锁 | 持锁直到事务完成，回滚先清理后解锁；管理员删除锁内重查 file/CBTI 引用，软删除也保护；Redis 不可用或对象忙时不放行 |
| Server S3 | 闪念创建统一应用服务事务 | 主体与关联事件一起提交/回滚；HTTP/MCP 均校验嵌套参数 |
| Server S4 | 补固定基线升级验证与发布前结构预检 | 6 份迁移有顺序/摘要，CI 对比全量/升级库并验证旧数据与关键约束，提供 SELECT-only 预检 |
| Front F1 | 菜单 ID 全链路保留 string | API、路由、Tree、锁状态及保存参数不再对大整数执行 Number 转换 |
| Front F2 | 唯一导航刷新入口，先生成可用快照 | 统一显示偏好/锁标记，失败保留旧路由，迟到刷新不发布 |
| Front F3 | 公共卡面列表防止陈旧响应覆盖写入 | 删除/启停/保存记录写入版本，与列表请求结果合并 |
| Front F4 | CI 在构建前检查类型和关键回归 | 主仓新增三仓固定 SHA 的契约工作流；跨仓发布需更新版本锁 |
| Mobile M1 | 账单删除后重建分页快照 | 单删/批删均不跳过后续记录，刷新失败保留内容并可重试 |
| Mobile M2 | 写入和下拉刷新同时同步列表与统计 | 月度概览/年度明细独立加载与错误恢复，旧请求不能覆盖写入后的数据 |

Server 的存储修复补齐了审查后发现的 CBTI 图片引用路径，仍属于同一上传/删除一致性问题。保留工作区原有及其他并行任务的改动，不把其他安全任务的成果计入此表。

## 交付边界

- 本轮没有执行 Git 提交、推送、生产迁移或部署；新 CI 的远端结果未验证，静态语法通过不代表 GitHub Actions 已跑通。
- 数据库升级的 CI 目标为 MySQL 8.0；本地 Docker daemon 未响应，因此本地使用独立 MySQL 9.5，不能当作 MySQL 8.0 验收。临时数据库实例已停止并清理，验证元数据保留在被忽略的 artifacts 目录。
- 部署对象锁改动时应同步升级上传/删除实例，混合旧实例期间暂停管理员清理。仍需真实 Redis/MinIO 并发验收。
