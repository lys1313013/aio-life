## 已确认问题

### M1 · P2：删除已加载账单后继续分页会漏掉未加载记录

**位置**：`/Users/hurry/Documents/GitHub/lys1313013/aio-life/aio-life-mobile/src/pages/finance/ledger.uvue:326`（单条删除）、`:345`（批量删除）、`:189`（下一页计算）。

**触发**：账单数量超过 50，加载第一页，删除第一页中的一条，再滚动加载第二页。删除成功只过滤本地 rows、减少 total，保留原 page。服务端 offset 分页中的后续记录已经向前移动，客户端仍请求下一页的固定偏移。

**复现结果**：直接抽取当前 `.uvue` 的 script，经 esbuild 转译执行；模拟服务端初始 101 条记录、每页 50 条。加载首 50 条、删除 ID 1、加载第 2 页，得到 `loaded=99,total=100,missingIds=['51']`。再次请求后续空页也找不回 ID 51。批量删除会跳过更多记录。

**影响**：收入和支出共用 Ledger，因此两者都受影响；并非仅显示计数错误，用户确实无法在本次滚动结果中看到被跳过的账单。服务端记录没有被额外删除。

**建议**：成功删除后使分页快照失效，重新加载已展开范围或重置到第一页；更长期可使用稳定游标。抽出分页状态和 mutation 后的失效规则，至少统一覆盖去重、末页、删除偏移、筛选切换和失败页恢复。

**置信度**：高；执行当前源代码的纯模拟复现。**近期引入**：是，最近几天新增的客户端账单实现中已有；HEAD 中同样存在，并非本次服务目录搬迁引入。

### M2 · P2：保存、删除和下拉刷新不更新账单统计

**位置**：`/Users/hurry/Documents/GitHub/lys1313013/aio-life/aio-life-mobile/src/pages/finance/ledger.uvue:236`（下拉刷新）、`:308`（保存）、`:326`/`:345`（删除），统计数据加载在 `:47`，初始化调用在 `:228`。

**触发**：进入收入/支出页面后新增、编辑或删除账单。保存仅 `await load()`；删除只改 rows/total；下拉刷新也只调用 load。`overviewRows`、月度趋势、年度总额和分类分布保持首次进入时的数据。

**复现结果**：同样抽取当前 script 并替换网络为模拟服务。初始总额 100 元，新增一笔 200 元后执行页面 save 和 refresh，`statisticsCalls=1,displayedTotal=100,actualTotal=300`。列表已更新，统计仍旧；下拉操作无法修复。

**影响**：同屏列表与财务统计相互矛盾，可能误导对金额的判断。切换年度/月份统计等部分操作可重新请求，但正常保存及全页下拉并不保证一致性。

**建议**：定义统一的账单变更失效入口，成功写入后刷新列表及相应统计；页面下拉刷新覆盖所有可见数据，保留旧内容并给统计独立 loading/error。列表请求序号和统计请求序号仍应分离。

**置信度**：高；执行当前源代码的纯模拟复现。**近期引入**：是，近期账单概览实现中已有；HEAD 同样存在。

### M3 · P1 安全交叉发现：声明 GCM，实际落到 ECB

**位置**：`/Users/hurry/Documents/GitHub/lys1313013/aio-life/aio-life-mobile/src/pages/vault/services/vault-crypto.ts:29`、`:33`。

当前代码给 gm-crypto 传入字符串 `mode:'GCM'`。安装版本的 `types/index.d.ts` 仅声明 ECB/CBC；用完全模拟的固定 key/plaintext 调用安装的库，返回 `{gcmAccepted:true,equalsECB:true}`。因此不能将现有格式描述成带认证的 GCM。该格式为兼容 Web 而延续，本次服务目录搬迁没有新创造此问题。独立安全 agent 已复核，完整影响及双端兼容迁移见 security 报告；本条不在汇总中重复计数。

## 架构判断

| 方面 | 当前判断与依据 |
| --- | --- |
| 业务与公共边界 | 按业务分包移动服务合理；公共 query-path 拆出避免从另一个业务分包借用函数。扫描 901 个相对 import 链接，未发现缺失源文件。只证明文件路径存在，不证明所有运行时行为。 |
| 微信构建 | `scripts/weixin-package-policy.json` 作为依赖归属与预算唯一配置较清楚。插件从锁定 npm 依赖构建分包私有副本、保留许可证，并检查最终 require 跨包关系。未发现当前明确非法同步跨包引用；本次不重跑构建，README 中历史体积不是此次验证结果。 |
| 构建维护成本 | 对 uni 的 manualChunks 函数形状及产物 require 重写顺序有耦合，但当前已有失败即停止的保护。后续升级 DCloud 时应以少量编译 fixture 验证各分包与导出，不能仅依赖文件体积；属于演进建议，当前没有证据认定插件本身坏了。 |
| 请求与会话 | api.ts 对普通请求验证 Token 是否仍为当前会话；菜单缓存有 generation、TTL 与同步 Token watch；目录缓存按 Token 指纹隔离。记录页 scope 与 domain page 生命周期也有离页/换账号失效。没有据此发现普通请求跨账号写回的确定漏洞。 |
| 状态生命周期 | `createRecordScope`、`useDomainPage`、各页 alive/generation 和个别 latest-task 并存。可按“页面可见性、会话、请求、表单”的不同生命周期逐步统一，不应简单用一个全局序号替代所有维度。M1/M2 正是业务失效规则缺少统一约定后的具体后果。 |
| UI 基础 | MobilePage、FormField、FormActions、AdaptiveModal 和 spacing/typography 配置形成可复用层，优于每个页面单独实现。样式规范检查只能验证规则，不能替代手机/平板/桌面实际截图。 |
| 契约 | api-payload.ts 从后端生成并在请求边界选择字段，保留字符串 ID/null 等语义，方向正确。测试覆盖多个动态路由和真实 uni.request 边界。独立 mobile CI 不能单靠本地 fixture 证明与最新 server 永远同步，应在跨仓库交付时记录契约版本并运行生成差异检查。 |
| 测试 | 既有服务契约测试、生命周期模拟、H5 页面交互/图表像素测试有实际价值，不能说“只有快照测试”。但 M1/M2 缺少“写入后再分页/再刷新统计”的序列覆盖；当前用例数量不足以证明长操作链一致性。 |
| 跨端边界 | Web/微信条件编译、native-files 和随机数 UTS 桥接有所隔离。README 已说明 App 编译器与 HBuilderX 不匹配及未真机验收。本次不将该边界写成已验证的 App 兼容性，也不因未真机测试就虚构代码缺陷。 |

## 建议顺序

1. 发布前：与 Web 协调修复 M3 的版本化密文协议；先处理 M1/M2 并加入仅使用模拟账单的完整操作序列回归。

3. 分包维护：为自定义 vendor 插件补少量固定输入/输出 fixture，覆盖主包误引入、跨包 require、动态编码表导出；升级 uni 工具链才扩大验证范围。
