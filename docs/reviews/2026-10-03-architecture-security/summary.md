# AIO Life 三端架构与安全审查汇总

日期：2026-10-03（Asia/Shanghai）。本轮由 3 个架构子智能体与 1 个独立安全子智能体并行审查，主智能体交叉复核、去重和统一定级。

## 结论

**三端的基础架构合理，不需要推倒重做，也没有拆微服务或更换前端框架的依据。当前更需要补安全边界、写入后的状态一致性与交付门禁。** 最近的大量修改中，Req/Query/VO 收敛、公共组件统一和业务依赖下沉微信分包都是正确方向；风险来自改造没有贯通所有调用端，以及已有缺陷随新客户端扩大覆盖面。

| 项目 | 判断 | 应优先治理的边界 |
| --- | --- | --- |
| server | 保持按领域划分的模块化单体；微信客户端、票据、账户事务、会话签发的拆分合理 | 跨表事务、数据库与 Redis/MinIO 一致性、增量数据库升级验证；逐步让 HTTP/MCP 共用应用服务 |
| front | 保留 Vben monorepo、应用 adapter、业务 API 和领域页面 | 字符串 ID 全链路、唯一的菜单重建入口、请求与写入竞态、把已有单测和类型检查放入 CI |
| mobile | 保留 Vapor、公共基础组件和按业务分包；服务及重量库下沉合理 | 分页在删除后的失效、列表与统计同步、跨仓库契约版本、构建插件升级验证 |

详细证据、触发条件与行号见 [Server](server.md)、[Front](front.md)、[Mobile](mobile.md)、[安全专项](security.md)。本文件只汇总，不把重复发现计为多个问题。

去重后汇总：**5 项 P1，11 项 P2**；P2 中包括前端 CI 与数据库升级的验证缺口。安全报告另列尚依赖生产配置核实的风险，不混入已确认问题计数。

## 优先处理的安全问题

1. **密码库并未按 GCM 加密。** Web 与 Mobile 都向 gm-crypto 传入字符串 `GCM`；两个子智能体分别用模拟输入确认结果与 ECB 一致。需要版本化迁移到实际支持的认证加密协议，兼容读取旧密文，不能直接替换模式导致历史密码无法解密。
2. **敏感认证参数仍可能进入通用请求日志。** 微信控制器已被排除，但注册、重置密码、二级验证等入口仍可能整包序列化密码/验证码。应对认证及密钥字段统一实行日志白名单/脱敏，并评估历史日志留存。
3. **普通上传及预览存在存储型脚本执行链。** 头像等普通上传信任调用方 Content-Type，公开预览原样返回，可形成 HTML 在 API 域下执行的路径；银行卡的专属图片校验没有覆盖普通上传。需要按业务校验内容并安全预览，是否能影响 Web 会话取决于实际同源部署，不能据源码断言所有部署均能窃取 Web Token。
4. **封面抓取存在 SSRF 路径。** 阅读/观影请求中的封面 URL 可以进入服务端 HTTP 抓取，响应后检查图片类型无法阻止请求内网。需要在请求前校验目标、DNS 解析结果与每次重定向，并限制出站地址、时间和响应大小。
5. **账号删除后旧凭据未撤销。** 逻辑删除用户未同步撤销 Token/API Key，常规请求也不统一复核用户是否仍有效；密码找回同样未撤销旧会话。需要补齐账户生命周期和凭据撤销，并覆盖普通及微信登录签发的会话。

上述为 P1 优先整改项，主要是既有问题，不能归因为全部由微信登录引入。账户生命周期、条件性风险和已存在的保护措施以安全专项为准；没有对生产服务实施利用。

## 微信登录专项判断

当前已核验的正面保护包括：服务端交换微信凭证；loginCode 与 phoneCode 分离；随机票据短期有效且 Redis 原子消费；手机号冲突不自动合并账户；绑定要求业务会话与原密码；首次设密校验新鲜微信身份且不能覆盖已有密码；数据库唯一约束及事务处理并发；微信认证请求参数不进入通用日志；临时票据不被客户端保存为业务 Token。

**本轮未发现仅伪造客户端手机号就能接管旧账号的路径，但不能据此认定系统已经安全。** 微信绑定复用的原账号登录仍缺应用级限流，所签发的 Token 也受既有账户撤销问题影响。真实微信授权、目标 MySQL 升级、反向代理后的限流表现与真机链路没有在本轮验证。

## 整改顺序

1. 先修 P1 安全链路；密码库先确定版本化协议和旧数据迁移方案。用小批次提交隔离日志、文件预览、URL 抓取和加密改造。
2. 修已复现的菜单、卡面竞态、账单分页/统计问题，并补对应操作序列回归；修复后验证，不以本轮旧用例通过替代回归。
3. 补安全配置缓存的可靠失效、文件上传/清理协调及跨表事务；加入故障与并发用例。
4. 完善前端 CI、三仓固定 revision 的契约校验和 MySQL 增量升级门禁，再渐进整理 Controller/MCP 与页面公共状态逻辑。避免为“架构整洁”再做一次跨全仓的大规模移动。

- 微信：20 项隔离测试通过，微信/Redis/账户依赖为 mock，不是真实微信联调。
- Mobile：直接执行当前页面脚本的两个模拟场景复现分页/统计问题；901 条相对 import 路径检查未发现缺失文件。加密模式使用模拟密钥和明文验证，没有读取真实密码。
- 未运行全仓构建/全量测试、线上 API 验收、实际数据库迁移、微信或 App 真机验证。没有提交、推送、部署或修改业务源码。
- 审查期间 server/mobile 的其他工作仍在修改文件；已复核相关结论，报告代表读取时的工作区快照，不是一个不可变提交的发布认证。特别是 Ledger 两个问题在专项收尾时仍存在，哈希记录在 mobile.md。
