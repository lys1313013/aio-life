# 首页快捷导航 — 需求方案

> 当前已提供用户布局、候选查询和保存；接口、跨端保留规则及部署入口见[技术实现](首页快捷导航-技术方案.md)。下文保留需求与验收项，不以复选框状态代替当前版本验收。用户未添加任何项时不预置入口。

---

## 一、范围

**In Scope**

- 用户可对快捷导航进行**增、删、排序、启停**
- 候选池 = 当前用户可访问的**叶子菜单**（复用 `/menu/all` 的角色过滤）
- 后端持久化，跨设备同步

**Out of Scope**

- 管理员预置默认项 / 新用户首屏自动套用
- 自定义标题 / 图标 / 颜色 / URL（展示字段锁定为菜单 `meta`）
- 多套布局 / 跨用户共享

---

## 二、用户故事

1. **首次进入 / 未添加时**：导航区为空态卡片（"+"格 + 提示文案），不出现任何入口。
2. **添加**：编辑态 → "+ 添加" → 菜单树里勾选 → 保存。
3. **删除 / 排序 / 停用**：编辑态下操作，单项完成。
4. **清空全部**：编辑态下"清空"按钮，二次确认后保存为空布局，首页回到空态。

---

## 三、字段设计

新表 `user_quick_nav`：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| user_id | BIGINT | 用户 ID |
| menu_id | BIGINT | 关联 `sys_menu.id` |
| sort_order | INT | 排序号 |
| enabled | TINYINT(1) | 1 启用 / 0 隐藏 |
| create_time / update_time | DATETIME | |

当前结构使用主键和用户排序索引，重复菜单由保存逻辑校验；不再使用早期草案的 `(user_id, menu_id)` 唯一索引。标题、图标、颜色与 URL 不存副本，读取时批量补充菜单配置；颜色来自 `sys_menu.icon_color`。正式 DDL 以技术实现链接的全量 SQL 为准。

`sys_menu` **不**新增字段。

---

## 四、UI 行为

**空态**（未保存任何项）：虚线边框包裹的居中卡片，含大号"+"格 + "添加你的第一个快捷方式"主标 + 一行副标。整张卡片可点击，进入添加弹窗。

**默认态**（已有布局）：复用 `WorkbenchQuickNav`，右上角"编辑"图标进入编辑态。

**编辑态**：每项左上拖拽手柄 `≡`、右上 `×`、底部状态点 `●/⊘` 切换启停；末尾 "+"格；底部 [取消] [保存] [清空全部]。

**添加弹窗**：菜单树多选；已添加项禁用并标"已添加"；达 15 项上限后未选项禁用并提示。

---

## 五、边界

| 场景 | 行为 |
|------|------|
| 用户从未保存 | `GET /quick-nav/my` 返回 `[]` → 空态 |
| 用户清空当前端 | 当前端返回空布局；保留另一端独有配置 |
| 候选池为空 | 空态保留，但"+"格与"编辑"置灰并提示"暂无可添加的菜单" |
| 菜单被管理员禁用 | 置灰不可点击；编辑态提示"该菜单已停用" |
| 菜单被管理员删除或失去权限 | 读取时过滤，不承诺立即物理删除用户布局行 |
| 超过 15 项 | 前端拦截；后端检查当前提交及保留另一端独有项后的合计 |
| 加载失败 | "加载失败，点击重试"占位，编辑按钮禁用 |

---

## 六、验收

- [ ] 新用户 / 未保存用户进入首页，**快捷导航为空态**，不出现任何入口
- [ ] 点击空态卡 / "编辑" → 添加弹窗 → 选 N 项 → 保存 → 渲染已保存布局
- [ ] 增 / 删 / 排序 / 启停 / 清空全部 均生效
- [ ] 取消编辑后未保存改动丢弃
- [ ] 保存后刷新 / 换设备登录 布局一致
- [ ] 达 15 项上限时 "+" 禁用并提示
- [ ] i18n / 暗色模式 / 移动端可用
