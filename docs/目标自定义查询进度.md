# 目标自定义 GraphQL 进度

当前实现：2026-11-03。目标可选择手动填写或保存任意符合 Query 已发布 Schema 和只读权限的 GraphQL。用户可编辑查询、固定变量、日期绑定、结果路径及达到/超过条件，不要求预先注册指标类型。普通客户端不直接持有 Hasura 管理凭据。

编辑交互更新（2026-11-10）：Web 与移动端仅从 GraphQL 变量声明生成通用输入表单，不识别分类、收入或运动字段，也不读取业务字典生成特殊下拉框。字符串变量可填写固定值或选择目标起止日期 / 月份作为来源；已有日期绑定还原为中文选项，新变量不猜测来源。分类名称作为普通字符串提交，具体关联和筛选由 Query 已发布的 Schema 与派生 SQL 实现。例如 `category: { name: { _eq: $categoryName } }` 的 `categoryName` 可输入“休息”，前端不查名称对应的 ID。预览和保存仍生成原有 `progressVariables` / `progressVariableBindings`，不要求手写两块 JSON；复杂对象或列表变量保留单变量 JSON 编辑，接口与存储结构不变。

## 配置与计算

目标新增 `progressMode`、`progressQuery`、`progressVariables`、`progressVariableBindings`、`progressValuePath`、`targetOperator`；变量与绑定以 JSON 对象文本保存。`targetValue/currentValue` 为非负数，最多两位小数，最大 `999999999999.99`，业务 HTTP 返回 JSON 数字。

- `progressMode`: `manual` 或 `graphql`。切回手动清除查询和计算状态；自动模式拒绝手动覆盖当前值。
- `progressValuePath`: 相对于 GraphQL `data`，例如 `progress.exerciseCount.max`；可用 `rows.0.amount` 提取数组中的一个数值。别名由用户自由选择。
- 数值接受 JSON 数字或十进制数字字符串。路径不存在、对象、布尔、非法数字、负数、超范围或超过两位小数报错。已存在字段的 `null` 明确按空集合记为 0。
- `targetOperator`: `gte` 表示达到，`gt` 表示严格超过。`gt + 100` 在 100 时仍未达标，101 才达标；未达标进度最多显示 99%，已达标显示 100%。
- 自动计算的达标徽标与用户维护的目标 `status` 分离；不自动写入 `completedAt`，搁置状态保留。刷新失败保留最近成功值、时间和对应达标显示，同时展示错误。

日期绑定仅支持：

| 绑定 | 含义 |
| --- | --- |
| `goal.startDate` | 开始时间所属日期，`yyyy-MM-dd` |
| `goal.endDateExclusive` | 结束时间所属日期的下一天，右开边界 |
| `goal.startMonth` | 开始时间所属月份的第一天 |
| `goal.endMonthExclusive` | 结束时间所属月份的下个月第一天 |

例如 `{"start":"goal.startDate","end":"goal.endDateExclusive"}`。绑定需要有效起止时间，不与固定变量同名；不做查询文本替换，不提供用户身份绑定。周期按日期或整月比较，起止的时分秒不用于这四种日期绑定。固定变量可用于不跟随目标日期的查询。当前 Query 每次仍要求一个最多 366 天的日期范围；更长目标应自行选定合法统计窗口，当前不会自动拆分或合并多年聚合。

## 三个场景

配置文件同时可作为 `POST /api/goals` 的请求示例，类型 ID 均为虚构，必须替换为本人数据中的实际 ID：

| 场景 | 查询与结果路径 | 示例 |
| --- | --- | --- |
| 俯卧撑一次性 40 个 | 指定运动类型，`exerciseCount.max`，不是运动次数求和；模拟值 26/40=65% | [goal-pushups.json](https://github.com/lys1313013/aio-life-query/blob/main/examples/goal-pushups.json) |
| 零点在休息超过 80 天 | 当日 `startTime=0`、`endTime>=1` 且 `category.name=休息`，`date.countDistinct`；按覆盖零点的记录日期去重。“休息”只是用户的分类名称，不据此推断实际睡眠 | [goal-sleep.json](https://github.com/lys1313013/aio-life-query/blob/main/examples/goal-sleep.json) |
| 最高单月工资达到目标金额 | `income_month` 按用户、收入类型、自然月汇总 `income.amt` 后取 `monthlyAmount.max`；按实际工资收入类型筛选，不把其他收入算入 | [goal-salary.json](https://github.com/lys1313013/aio-life-query/blob/main/examples/goal-salary.json) |

月收入模型统计 `amt` 合计，未减 `tax`，不是税后工资推算；自然月模型包含目标起止日期所在的完整月份。派生 SQL 由开发者维护，用户只写 GraphQL，不接受用户 SQL。模型保留用户维度并排除逻辑删除，Hasura 对聚合和明细继续强制用户过滤，收入权限沿用 `/finance/income` 与 AI 工具二级锁。

## 接口、页面与运行

- `POST /api/goals/progress/preview`: 使用目标创建字段预览，返回当前值、百分比、是否达标和解析后的变量；不保存目标，不返回额外明细。
- `POST /api/goals/progress/refresh`: `{ "ids": ["目标ID"] }`，单批 1～10 个，不重复且全部属于当前用户。每批最多两个查询，查询等待预算为 12 秒，逐项目标返回 `progressError`；失败不把已有值写为零。
- Web 与移动端的目标页、首页固定目标会批量刷新；编辑器可编辑配置并执行预览，保存后刷新该目标。当前没有后台定时计算，不保存用户 Token。
- 业务后端设置 `AIO_LIFE_GOAL_QUERY_URL` 为后端可访问的 Query `/graphql` 地址。Query 原有授权开关、内部服务密钥、网络与只读账号配置继续生效。回环默认值仅适用于本机；容器部署使用对应服务名或内网域名。
- 预览遇到二级锁时，Query GraphQL 错误通过 `extensions.menuPath` 返回受控站内路径，业务后端还原 `code=2001`，客户端复用正常解锁弹窗；批量刷新保留失败快照及错误，不绕过锁。
- 后端转发当前请求的 Bearer 凭据，经 Query 的统一鉴权、配额和审计。目标不能指定远端地址、Hasura 角色、管理密钥或其他用户身份。
- 查询配置或日期变化清空快照；每次编辑递增 `progressVersion`。外部查询完成后只写回同一修订，编辑或删除后的旧响应不覆盖新配置；内部 `progressRefreshId` 另外阻止同一配置下较早的刷新覆盖较新刷新，不作为客户端字段。

## 数据库与验证

当前 PostgreSQL 初始结构已包含目标 GraphQL 进度字段，升级入口见[数据库初始化与验证](../aio-life-server/docs/数据库初始化与验证.md)。原 MySQL 增量仅在 [Git 历史](https://github.com/lys1313013/aio-life-server/blob/1911edda35fae5b6b10a19216885d4f7e1a4843c/sql/migrations/V20261103_01__goal_graphql_progress.sql)中追溯。后续新增 V，不改已执行迁移。新增 Query 能力需同步部署网关、元数据、Connector 配置，并补充收入源列 SELECT 权限。

真实查询及业务保存/刷新验收入口：在 `aio-life-query` 执行 `python3 scripts/test_goal_progress.py`，需要 JDK 21、Docker、已构建的 Connector 和网关 JAR，以及相邻后端仓库。脚本创建临时 PostgreSQL、Redis、Hasura 和本地授权桩，读取当前 PostgreSQL 结构并执行真实链路；退出清理资源，不访问业务库。此验收不代替生产身份/网络联调或微信真机、App 验证。

## 类型名称关联（2026-11-11）

运动查询使用 `exerciseType: { name: { _eq: $exerciseTypeName } }`，固定变量直接填写“俯卧撑”；月收入查询使用 `incomeType: { name: { _eq: $incomeTypeName } }`，固定变量直接填写“工资”。与时迹的 `category.name` 一样，关联由 Query 的受控派生 SQL 完成，前端不映射业务字段、字典接口或 ID。

运动、收入类型名称遵守用户字典的公共项、个人覆盖与只读标签规则。停用项保留历史名称，删除、其他用户或错误字典域不返回类型关系。同名类型均可匹配；收入仍按类型主键和自然月分组，同名类型不自动合并。名称变更后，名称筛选使用当前有效标签。
