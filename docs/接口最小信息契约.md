# 接口最小信息契约

Controller 使用独立的请求、查询、响应模型，持久化 Entity 只在内部流转。接口保留完成当前操作、展示页面和维持业务关联所需的数据，不再把数据库行或列表对象整体作为输入输出契约。

## 请求边界

- 创建只接收可写业务字段；服务器生成 ID，并从登录态填写用户和审计信息。
- 更新的 ID 在 URL 中时，请求体不再重复传 ID；根路径更新仍要求请求体中的 ID。
- 排序只接收目标 ID、顺序和确需的分组位置；公共分类覆盖允许使用 `templateId`。
- 查询只声明真正参与过滤的条件，不使用 `CommonQuery<Entity>`。Web 继续将 `condition` 平铺为 GET 参数。
- 时迹运动子项只接收运动类型、数量、描述；归属、日期和时迹关联由后端确定。想法事件只接收事件 ID 和内容。
- `fileIds` 未传表示保留附件，空列表表示清空。显式 `null` 不被前端字段选择器丢弃；分类 `parentId` 未传与显式 `null` 仍能区分。
- B 站进度同步支持不存在时创建记录，因此保留创建所需的视频信息。
- MCP 工具参数、CBTI 答案、MBTI 算法结果和第三方数据的动态结构按各自业务契约保留。

## 响应边界

- 显式 VO 映射移除非业务所需的所属用户、创建者、修改者和逻辑删除等字段，包括嵌套对象。
- 财务表格的记录时间、想法及关联事件的展示时间、字典维护时间等有实际展示用途，继续返回。
- 公共字典、时迹分类的 `userId` 用于判断公共或个人范围，继续保留；分类隐藏状态改为业务字段 `isHidden`。
- 观影、阅读和消息管理分页统一返回 `{ items, total }`，不暴露 ORM 的分页配置字段。Web 列表、两端关联选择器及移动端列表已同步。
- MBTI 历史列表不返回原始结果；结果详情按需提供结果页面与四类分析数据。
- 后端大整数 ID 仍以字符串返回，前端以字符串使用。

后端、Web、移动端只使用当前最小字段契约，配套更新。

## 前端契约维护

Web 的 `apps/web-antd/src/api/payload.ts` 与移动端的 `src/services/api-payload.ts` 由主仓库脚本根据后端 Controller 和请求模型生成，不手工修改。生成与检查步骤统一见 [API 参数规范](API参数规范.md#契约生成与验证)，交付使用[本地统一推送入口](API参数规范.md#本地统一推送与联合检查)。

Web 在 API 发送处调用 `pickPayload` / `pickPayloadList`，避免把只读字段、审计字段和客户端派生字段回传。移动端动态业务路由在统一请求边界调用 `minimalRequestPayload`。GET 选择支持的过滤条件，保留 `false`、零及字符串 ID。未知路由保持原有行为，文件上传、流式响应和动态工具数据按原有专门入口处理。

## 验证入口与边界

后端验证入口为 `ApiBoundaryContractTest` 及 OpenAPI 契约测试；Web、移动端验证请求边界与生成契约。关系型数据库方言、事务和约束须另在真实隔离 PostgreSQL 验证，局部模拟或 H2 夹具不能替代。

原本地测试数量、时迹浏览器失败及未验证平台见[历史验证记录](reviews/2026-11-11-interface-contract-history/README.md)。原记录未注明执行日期，不能据此声称当前版本验收通过。
