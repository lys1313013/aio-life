# 时迹需求方案

## 一、概述

时迹（Time Tracker）是 AIO Life 的核心记录引擎，以分钟为粒度记录每日时间分配，支持分类标签、关联业务（阅读/观影）、运动记录，并提供智能分类推荐。

---

## 二、数据模型

### 1. 时间记录（time_record）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 唯一标识 |
| userId | long | 用户 ID |
| categoryId | string | 分类 ID |
| date | date | 日期 |
| startTime | int | 开始时间（分钟，0-1439，含起点） |
| endTime | int | 结束时间（分钟，0-1439，含终点） |
| duration | int | 持续时长（分钟，由 start/end 自动计算） |
| title | string | 标题 |
| description | string | 备注 |
| relateType | int | 关联业务类型（1=阅读，2=观影） |
| relateId | long | 关联业务 ID |
| isManual | long | 是否手动添加 |

- startTime/endTime 最大值限制为 1439（23:59）
- duration = endTime - startTime + 1（闭区间）
- 逻辑删除（is_deleted）

### 2. 分类（time_tracker_category）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | long | 唯一标识 |
| userId | long | 用户 ID（0=公共分类） |
| templateId | long | 模板 ID，指向被覆盖的公共分类 |
| name | string | 分类名称 |
| color | string | 颜色值（Hex） |
| icon | string | 图标（Iconify 格式） |
| timeType | int | 时间类型：1=必须时间，2=积极时间，3=消极时间 |
| isTrackTime | int | 是否记录时间 |
| isEnabled | int | 是否启用 |
| sort | int | 排序权重 |

- 用户可基于公共分类创建个人覆盖（templateId 指向公共分类）

### 3. 运动记录（exercise_record）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 唯一标识 |
| userId | long | 用户 ID |
| timeId | string | 关联的时间记录 ID |
| exerciseTypeId | string | 运动类型 ID |
| exerciseCount | int | 运动次数/数量 |
| exerciseDate | date | 运动日期 |
| description | string | 备注 |

- 一条时间记录可包含多条运动记录（1:N）
- 编辑时先删后插，保证数据一致

## 三、功能模块

### 1. 时间记录 CRUD

- **新增** `/timeRecord/save`：录入时间块，自动计算 duration，关联业务状态联动
- **编辑** `/timeRecord/update`：修改任意字段，运动记录先删后插
- **删除** `/timeRecord/delete`：按 ID 删除单条
- **批量删除** `/timeRecord/deleteByDate`：按日期删除当天全部记录
- **查询（分页）** `/timeRecord/query`：按日期分页查询
- **查询（日期范围）** `/timeRecord/queryByDateRange`：按日期范围查询
- **查询（AI 接口）** `/timeRecord/queryByDateRangeForAI`：按日期范围查询，附分类名称，按时间倒序
- **单条查询** `/timeRecord/{id}`：含关联运动记录
- **距上次记录时长**：返回距当天最后一条记录或 00:00 的时长描述（如"2小时30分"）

### 2. 关联业务状态联动

录入/更新时间记录时，如果关联了阅读或观影业务，且该业务状态为「未开始」，自动变更为「进行中」。

| 关联类型 | 枚举值 | 关联表 |
|----------|--------|--------|
| 阅读 | 1 | read_record |
| 观影 | 2 | movie |

业务状态枚举：
- 0 = 未开始
- 1 = 进行中
- 2 = 已完成
- 3 = 搁置

### 3. 分类推荐

#### 入口：`/timeRecord/recommendType`

参数：`date`（日期）、`time`（分钟数）、`previousCategoryId`（可选，紧邻上一条记录的分类）

#### 算法流程

```
Step 0: 计算参考日期
  - 周一 → 上周五（-3天）
  - 周六 → 上周日（-6天）
  - 其他 → 前一天（-1天）

Step 1: 查参考日期同一时间段是否有记录
  SQL: date = 参考日期 AND startTime <= time <= endTime
  有结果 → categoryId = 记录的分类

Step 2: 如果 Step 1 未命中，降级到时间段历史高频
  SQL: 统计历史上该 time 时间段所有分类，按频次降序取第一
  区分工作日/休息日

Step 3: 去重干预（categoryId != null && categoryId == previousCategoryId）
  3.1 预测后续行为
    SQL: 历史上紧跟在 previousCategoryId 之后最常出现的分类
    （自连接，next.startTime = prev.endTime + 1，同一日期内无缝衔接）
    区分工作日/休息日
    有结果 → 返回

  3.2 降级到时间段高频（排除 previousCategoryId）
    SQL: 同 Step 2，但 excludeCategoryId = previousCategoryId
    有结果 → 返回

  3.3 实在没有其他分类 → 返回原推荐（允许连续相同）

Step 4: 返回 categoryId（可能为 null）
```

#### 关键 SQL

**getMostFrequentNextCategory**：自连接 time_record，找同一用户、同一天内，紧跟在指定分类之后（时间无缝衔接）的最高频分类。

**getMostFrequentCategoryAtTime**：统计指定时间段（startTime <= time <= endTime）内各分类出现次数，取最高频。可传入 excludeCategoryId 排除特定分类。

**recommendType（原逻辑）**：查指定用户、指定日期、指定时间段的记录。

### 4. 时间块推荐

#### 入口：`/timeRecord/recommendNext`

参数：`date`（日期）

算法：扫描当天已录入的记录，找到第一个时间空隙，自动计算推荐的 startTime/endTime，然后调用 `recommendType` 填充分类。

- 当天：结束时间取当前时刻
- 非当天：结束时间 = 开始时间 + 30 分钟
- 空隙前紧邻记录的 categoryId 作为 `previousCategoryId` 传给推荐算法

## 四、API 接口汇总

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/timeRecord/query` | 分页查询 |
| POST | `/timeRecord/queryByDateRange` | 日期范围查询 |
| POST | `/timeRecord/queryByDateRangeForAI` | 日期范围查询（AI 用，含分类名） |
| GET | `/timeRecord/{id}` | 单条查询（含运动记录） |
| POST | `/timeRecord/save` | 新增 |
| POST | `/timeRecord/update` | 编辑 |
| POST | `/timeRecord/delete` | 删除单条 |
| POST | `/timeRecord/deleteByDate` | 按日期批量删除 |
| GET | `/timeRecord/recommendType` | 分类推荐 |
| GET | `/timeRecord/recommendNext` | 时间块推荐（含分类） |
| GET | `/timeRecord/relateTypes` | 获取关联业务类型列表 |
