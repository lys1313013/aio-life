# 微信小程序一次性订阅消息

## 当前范围

第一版只支持 **力扣未打卡提醒**（`LEETCODE_REMINDER`），复用现有微信小程序登录绑定、通知偏好和通知投递表。不需要公众号，不引入新的数据库表。已有数据库需先完成原有微信登录和通知渠道迁移。

通知默认关闭。用户在微信小程序「我 → 通知设置」点击「订阅一次」后，仅当该模板返回 `accept`，才启用当前用户的微信提醒偏好。一次有效订阅对应该模板的一次发送机会；业务开关和“总是保持以上选择”都不代表无限推送。系统不根据客户端结果展示或累计“剩余次数”，真实可发送资格以微信发送接口为准。

Web、H5 和 App 可以查看状态、修改业务偏好，订阅授权在微信小程序中完成。第一版未接入每日一题和反馈通知的微信发送。

## 1. 选取模板

1. 登录 [微信公众平台](https://mp.weixin.qq.com/)，进入当前小程序的「订阅消息」。
2. 按真实业务及小程序服务类目选择适用于提醒的一次性模板，记录模板 ID、每个字段的类型和完整字段名。
3. 当前实现支持 `thingN`（标题或提醒内容）和 `timeN`（提醒生成时间）。`N` 是微信模板中的实际编号，不能照抄示例编号。模板若要求其他类型的字段，需要先扩展服务端字段映射；不能少传必填字段或用不相关模板代替。
4. 核对模板使用范围、主体能力和小程序发布状态。没有合适模板时先保持渠道关闭；模板是否可用以微信后台及实际发送结果为准。

相关资料：[订阅授权接口说明](https://uniapp.dcloud.net.cn/api/other/requestSubscribeMessage.html)、[腾讯云订阅消息实践](https://cloud.tencent.cn/document/product/1301/103770)。

## 2. 配置后端

复用已有配置 `AIO_LIFE_WECHAT_MINI_ENABLED=true`、`AIO_LIFE_WECHAT_MINI_APP_ID`、`AIO_LIFE_WECHAT_MINI_APP_SECRET`。服务端 AppID 必须与接收订阅的小程序一致；用户的 `wechat_openid` 只适用于这一小程序。更换 AppID 不能沿用旧绑定。

新增环境变量：

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `AIO_LIFE_WECHAT_SUBSCRIBE_ENABLED` | `false` | 开启试点渠道 |
| `AIO_LIFE_WECHAT_SUBSCRIBE_TEMPLATE_ID` | 空 | 微信后台选用的模板 ID |
| `AIO_LIFE_WECHAT_SUBSCRIBE_TITLE_FIELD` | `thing1` | 接收提醒标题的字段；模板不需要时设空 |
| `AIO_LIFE_WECHAT_SUBSCRIBE_CONTENT_FIELD` | `thing2` | 接收提醒内容的字段；模板不需要时设空 |
| `AIO_LIFE_WECHAT_SUBSCRIBE_TIME_FIELD` | `time3` | 接收提醒生成时间的字段；模板不需要时设空 |
| `AIO_LIFE_WECHAT_SUBSCRIBE_ENVIRONMENT` | `formal` | 点击通知打开的版本：`formal` 正式、`trial` 体验、`developer` 开发 |
| `AIO_LIFE_NOTIFICATION_ENCRYPTION_KEY` | 沿用通知配置 | 加密投递载荷的主密钥，至少 16 位；生产须自行配置并安全保存 |

例如，实际模板只有「提醒内容 `thing4`」和「提醒时间 `time2`」，则配置：

```dotenv
AIO_LIFE_WECHAT_SUBSCRIBE_ENABLED=true
AIO_LIFE_WECHAT_SUBSCRIBE_TEMPLATE_ID=<template-id-from-wechat-console>
AIO_LIFE_WECHAT_SUBSCRIBE_TITLE_FIELD=
AIO_LIFE_WECHAT_SUBSCRIBE_CONTENT_FIELD=thing4
AIO_LIFE_WECHAT_SUBSCRIBE_TIME_FIELD=time2
AIO_LIFE_WECHAT_SUBSCRIBE_ENVIRONMENT=trial
```

以上是字段映射示例，不保证模板库存在对应模板。标题及内容按 Unicode 字符截取最多 20 字，时间格式为 `yyyy-MM-dd HH:mm`。AppSecret、Token、真实用户身份不得写入客户端、Git 或日志。调用微信接口所需的服务器出口 IP 白名单等配置，以当前小程序后台要求为准。

## 3. 体验流程

1. 配置并重启后端，部署本次客户端代码。微信本地工程 AppID 仍只保存在 Git 忽略的 `src/project.config.json`。
2. 在微信开发者工具或真机中使用微信登录当前 AIO Life 账号，打开「我 → 通知设置」。未绑定时先完成微信账号绑定。
3. 点击「订阅一次」，同意模板订阅，看到「已订阅一次」。授权必须由用户点击触发，不在进入页面时自动弹出。
4. 点击「发送测试」，再确认「发送测试将消耗一次订阅机会」。成功后检查微信通知；点击消息应打开 `pages/coding/leetcode`。
5. 测试会使用同一提醒模板并消耗一次机会。要继续测试真实业务提醒，请再次订阅，并确认已绑定力扣账号、微信业务偏好开启。
6. 正常业务沿用现有力扣未打卡检查任务和触发条件，微信消息入队后由每分钟扫描任务发送；已有打卡记录不创建该提醒。服务端 `AIO_LIFE_SCHEDULING_ENABLED` 必须开启，测试发送接口则立即尝试发送。

测试接口每用户限频 30 秒。测试仅向服务端根据当前登录用户查到的微信身份发送，不接受客户端传入 `openid` 或任意收件人；测试用于验证渠道，不受用户的业务提醒开关影响。

## API

下表路径不含统一 `/api` 前缀，均要求登录：

| 方法 | 路径 | 含义 |
| --- | --- | --- |
| `GET` | `/notification/channels/wechat-mini` | 返回渠道是否可用、账号是否绑定、业务类型和模板 ID；不返回微信身份和密钥 |
| `POST` | `/notification/channels/wechat-mini/test` | 立即发送测试；无可用订阅机会时提示重新订阅 |
| `GET` / `PUT` | `/notification/preferences` | 沿用业务偏好接口，渠道值为 `WECHAT_MINI`，仅支持 `LEETCODE_REMINDER` |

## 投递与故障处理

- `notification_delivery.channel=WECHAT_MINI`，载荷包含入队时的 AppID、接收身份、模板、版本和字段数据，使用现有 AES-GCM 加密。
- 业务事件按接收用户、渠道和 `dedupKey` 去重，分布式事件锁内提交入队记录，避免多实例重复入队。
- 发送前重新检查渠道配置、账号绑定和业务偏好；配置或身份变化后取消旧投递，跨日未发出的提醒标记过期。
- 请求发送前先提交 `SENDING`。明确返回 `errcode=0` 才标记 `SUCCESS`；无授权（`43101`）、模板无效等标记 `FAILED`，不自动重试。
- 明确的 Token 失效、系统繁忙或限流按 1、5、30、120 分钟退避重试。取得 Token 前的预期服务异常也可重试。测试消息不后台重试。
- 发送接口超时、无法解析响应或缺少明确错误码记为 `UNKNOWN`；进程在请求发送后退出可能留下 `SENDING`。两种状态都不自动重新发送，先核对微信接收情况，避免重复消费订阅机会。
- 一次性订阅不保证每天长期触达。没有额度时，用户需要重新进入小程序订阅。对重要提醒可同时开启已有站内信、邮件或飞书渠道。

## 验证边界

原生授权通过 `tests/wechat-ui/run.mjs` 在隔离源码副本中模拟，覆盖授权同意/拒绝、重复点击、测试确认、无额度恢复、未开通、未绑定和三类视口深浅主题；不向生产页面注入模拟入口。

在移动仓库执行 `AIO_WECHAT_UI_ONLY=subscription node tests/wechat-ui/run.mjs` 可只验证本次订阅流程；不带该变量会同时运行已有微信登录和扫码确认专项。

没有真实模板时只能完成代码、模拟测试和编译验证，不能据此声称已真实发送、通过微信真机验收或正式发布。
