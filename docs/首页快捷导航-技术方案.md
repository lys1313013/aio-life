# 首页快捷导航技术实现

2026-10-23 按现有源码核对。业务需求见[快捷导航需求](首页快捷导航-需求方案.md)，图标与颜色见[共同规则](图标与颜色统一规则.md)。本文替换早期实现草案，不再复制 Entity、Store 与 DDL。

## 数据与保存规则

- `user_quick_nav` 保存 `user_id`、`menu_id`、`sort_order`、`enabled` 及公共审计／逻辑删除字段；实体继承 `BaseEntity`。
- 标题与图标来自菜单 `meta`，颜色来自菜单 `icon_color`，不在用户布局中存副本。读取布局时批量取菜单，再按权限与客户端过滤。
- Web、Mobile 和后端上限均为 **15 项**。后端还校验合并另一端独有项后的总数，不是每端各 15 项。
- 保存时校验必需字段、`enabled` 只能为 0／1、菜单和排序号不能重复、菜单必须在当前端授权集合内。
- 事务内逻辑删除旧布局并插入新布局；只替换当前端可配置部分，保留另一端独有项。`items: []` 清空当前端，不承诺清除另一端独有配置。
- 当前没有乐观锁版本字段；不能依赖前端草稿实现多设备并发合并。保存失败保留草稿，重新读取后再处理冲突。

正式结构以[冻结基线](../aio-life-server/sql/migrations/B20261028_00__baseline.sql)与后续 Flyway 版本迁移中的 `user_quick_nav` 为准。当前只有主键及 `idx_user_sort`，早期草案的 `(user_id, menu_id)` 唯一索引已不在正式结构中；不能再按草案创建索引或执行独立 DROP 表回滚。当前结构与初始化遵循[统一初始化流程](../aio-life-server/docs/数据库初始化与验证.md)。

## API

以下路径相对于 `/api`，使用现有 Bearer 鉴权；响应为 `{ code, message, data }`，整数 `code === 0` 才是业务成功。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/quick-nav/candidates?client=web` | 当前端授权叶子菜单候选 |
| GET | `/quick-nav/my?client=web` | 当前端已保存布局；未保存时 `data: []` |
| POST | `/quick-nav/my?client=web` | 保存当前端布局，返回最新可见布局 |

`client` 默认为 `web`，移动端使用 `mobile`。不提供 `/quick-nav/defaults`，新用户不自动填入默认项。

```json
{
  "items": [
    { "menuId": "9007199254740993", "enabled": 1, "sortOrder": 0 }
  ]
}
```

`menuId` 全程为字符串；用户归属来自登录态，请求不携带 `userId` 或审计字段。`enabled` 与 `sortOrder` 是数字。图标、标题、颜色、路径与 target 由服务端菜单补充，不随保存请求回传。

## 客户端行为

Web 的 `QuickNavSection` 使用本地草稿编辑；确认保存后通过 Store 更新布局。取消不写接口，首次加载失败时禁用基于未知布局的保存。拖拽排序还需保证移动触控可用。

移动端“全部 → 常用功能”与首页共用布局，使用按钮排序、启停与保存，不向网页版跳转传递 Token。服务、候选和保存请求均使用当前端参数；账号切换、离页或新请求开始后，旧响应不得覆盖当前状态。

无配置时不展示预置入口。图标、颜色和名称引用菜单配置；业务数据保持字符串 ID，不按菜单名称另写映射。加载和提交使用局部 loading，失败保留已有内容与编辑草稿。

## 验收要点

新增、删除、排序、启停、取消、清空、空候选、加载／保存失败都需覆盖；检查长 ID、重复菜单／排序号、无权限菜单、15 项边界、另一端配置保留、总数超限与跨账号旧响应。UI 另查手机、平板、桌面及深浅主题。本次仅核对文档与源码，没有重新执行业务测试、接口联调或设备验收。
