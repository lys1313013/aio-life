# 首页快捷导航 — 技术方案

> 配套文档：[首页快捷导航-需求方案.md](./首页快捷导航-需求方案.md)
> 本文档面向开发，描述数据模型、API、前后端实现要点、迁移与测试。

---

## 1. 总体设计

### 1.1 思路

复用现有菜单系统作为候选池。新增 `user_quick_nav` 表存用户最终布局；`sys_menu` **不新增任何字段**——管理员默认项能力已取消，用户未添加任何项时直接返回空列表。`/menu/all` 仍按角色返回全量路由树。

### 1.2 模块归属

| 关注点 | 模块 |
|--------|------|
| 数据库变更 | `aio-life-server/sql/` 新增 `user_quick_nav` 一张表 |
| 实体 / Mapper | `top.aiolife.system.pojo.entity`、`top.aiolife.system.mapper` |
| Service | `top.aiolife.system.service.IQuickNavService` |
| Controller | `top.aiolife.system.api.QuickNavController`（用户侧） |
| 前端 API | `apps/web-antd/src/api/core/quick-nav.ts`（新） |
| 前端 UI | `apps/web-antd/src/views/dashboard/home/components/QuickNavSection.vue`（从 `index.vue` 抽出） |
| 前端状态 | `apps/web-antd/src/store/quick-nav.ts`（新 Pinia store） |

### 1.3 关键技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 候选池来源 | 复用 `/menu/all` | 角色过滤已实现，不重复造轮子 |
| 用户布局存储 | 关系表（一项一行） | 与现有数据模型一致，便于排查 / 统计 |
| 保存策略 | 整块 POST 覆盖 | 避免合并逻辑、降低并发复杂度 |
| 默认项字段 | **不新增** | 用户未保存时直接空态，不做自动填充 |
| 空数据行为 | `GET /quick-nav/my` 返回 `[]` → 前端渲染空态 | 单一数据源，后端不"猜"前端要什么 |
| 图标 / 标题来源 | `sys_menu.meta` | 单一数据源，用户层不存副本 |
| 数量上限 | 8（写死常量） | 与"快捷导航"语义匹配；后续要做配置可加 |

## 2. 数据模型

### 2.1 DDL：`sys_menu` 不变更

本版本**不修改** `sys_menu` 表结构。`sys_menu` 仅作为候选池数据源被读取。

### 2.2 DDL：新表 `user_quick_nav`

新建文件 `sql/2026-06-05_create_user_quick_nav.sql`：

```sql
-- 用户快捷导航布局
-- 创建时间: 2026-06-05

CREATE TABLE IF NOT EXISTS `user_quick_nav` (
    `id`          BIGINT      NOT NULL COMMENT '主键',
    `user_id`     BIGINT      NOT NULL COMMENT '用户ID',
    `menu_id`     BIGINT      NOT NULL COMMENT '关联 sys_menu.id',
    `sort_order`  INT         NOT NULL DEFAULT 0 COMMENT '排序号',
    `enabled`     TINYINT(1)  NOT NULL DEFAULT 1 COMMENT '1启用/0隐藏',
    `create_time` DATETIME    DEFAULT CURRENT_TIMESTAMP,
    `update_time` DATETIME    DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `is_deleted`  TINYINT(1)  NOT NULL DEFAULT 0 COMMENT '逻辑删除',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_user_menu` (`user_id`, `menu_id`),
    KEY `idx_user_sort` (`user_id`, `sort_order`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
  COMMENT='用户快捷导航布局';
```

> ❗ 不存 `title/icon/color/url` —— 这些字段渲染时 JOIN `sys_menu` 实时取，避免数据漂移。

### 2.3 实体

新增 `top.aiolife.system.pojo.entity.UserQuickNavEntity`：

```java
@Data
@TableName("user_quick_nav")
public class UserQuickNavEntity {
    @TableId(type = IdType.ASSIGN_ID)

}
```

`SysMenuEntity` **不**新增字段。

## 3. 后端 API

所有响应统一 `ApiResponse<T>` 格式（`rscode: '0'` 为成功）。

### 3.1 用户侧（`/quick-nav`）

| Method | Path | 说明 | 入参 | 出参 |
|--------|------|------|------|------|
| GET | `/quick-nav/candidates` | 当前用户可访问、且适合作为快捷入口的菜单叶子列表 | — | `QuickNavCandidateVO[]` |
| GET | `/quick-nav/my` | 当前用户已保存的布局 | — | `QuickNavItemVO[]`（**可能为空数组**；空 = 渲染空态） |
| POST | `/quick-nav/my` | 整块覆盖保存（可传空数组，即"清空"） | `QuickNavSaveReq` | `QuickNavItemVO[]` |

> ⚠️ **不提供** `/quick-nav/defaults` 接口。需求已确认管理员默认项能力取消，用户未保存时直接返回 `[]`。

#### 3.1.1 VO 定义

```java
public record QuickNavCandidateVO(
    Long menuId,
    String title,    // 取自 meta.title
    String icon,     // 取自 meta.icon
    String color,    // 取自 meta.color，无则 null
    String path,     // sys_menu.path
    String target    // "self" | "blank"（meta.link 决定）
) {}

public record QuickNavItemVO(
    Long menuId,
    Integer sortOrder,
    Integer enabled,
    // 冗余展示字段，节省前端二次 JOIN
    String title,
    String icon,
    String color,
    String path,
    String target
) {}

public record QuickNavSaveReq(
    @Size(max = 8) @Valid List<Item> items   // 注意：允许为空数组（= 清空全部）
) {
    public record Item(
        @NotNull Long menuId,
        @NotNull Integer sortOrder,
        @NotNull Integer enabled
    ) {}
}
```

#### 3.1.2 保存逻辑

`QuickNavService.saveMy(userId, items)` 事务内：

1. 校验 `items` 中每个 `menuId` 都属于当前用户可访问集合（用 `menuService.getAccessibleMenuIds(roles)`）
2. 校验数量 ≤ 8、每个 `sortOrder` 唯一
3. **DELETE FROM user_quick_nav WHERE user_id = ?** （物理删除，配合 `is_deleted` 兜底可改为软删）
4. 批量 INSERT
5. 返回保存后的列表（JOIN `sys_menu` 填充展示字段）

并发：v1 不做版本号，last-write-wins。若两设备同时保存，后写者覆盖先写者。如需可后续在 `user_quick_nav` 加 `version` 字段做乐观锁。

### 3.2 管理员侧

**本版本无管理员侧 API。** 快捷导航完全由用户自助管理，管理员无需特殊操作；菜单管理页（`/system/menu`）的表单/列表**不**新增任何"快捷导航默认项"相关字段。

### 4.2 类型与 API 封装（`quick-nav.ts`）

```ts
import { requestClient } from '#/api/request';

export interface QuickNavCandidate {
  menuId: string;
  title: string;
  icon: string;
  color?: string;
  path: string;
  target: 'blank' | 'self';
}

export interface QuickNavItem {
  menuId: string;
  sortOrder: number;
  enabled: number;
  title: string;
  icon: string;
  color?: string;
  path: string;
  target: 'blank' | 'self';
}

export const QUICK_NAV_MAX = 8;

export async function getCandidatesApi() {
  return requestClient.get<QuickNavCandidate[]>('/quick-nav/candidates');
}
export async function getMyQuickNavApi() {
  return requestClient.get<QuickNavItem[]>('/quick-nav/my');
}
export async function saveMyQuickNavApi(items: QuickNavItem[]) {
  return requestClient.post<QuickNavItem[]>('/quick-nav/my', {
    items: items.map((i) => ({
      menuId: i.menuId,
      sortOrder: i.sortOrder,
      enabled: i.enabled,
    })),
  });
}
```

### 4.3 Pinia Store（`store/quick-nav.ts`）

```ts
import { defineStore } from 'pinia';
import { ref } from 'vue';
import { getMyQuickNavApi, saveMyQuickNavApi } from '#/api/core/quick-nav';
import type { QuickNavItem } from '#/api/core/quick-nav';

export const useQuickNavStore = defineStore('quick-nav', () => {
  const items = ref<QuickNavItem[]>([]);
  const loading = ref(false);

  async function load() {
    loading.value = true;
    try {
      // 直接使用后端返回值；空数组 = 空态
      items.value = await getMyQuickNavApi();
    } finally {
      loading.value = false;
    }
  }

  async function save() {
    items.value = await saveMyQuickNavApi(items.value);
  }

  async function clear() {
    items.value = await saveMyQuickNavApi([]);
  }

  return { items, loading, load, save, clear };
});
```

> `initialized` 字段已移除：业务上不再区分"用户是否保存过"，仅靠 `items.length === 0` 决定渲染空态。

### 4.4 容器组件（`QuickNavSection.vue`）

- props / events 与 `WorkbenchQuickNav` 保持兼容
- 内部状态：`isEditing: boolean`、`draft: QuickNavItem[]`（编辑态本地副本）
- 退出编辑态分两条路径：
  - `cancel`：丢弃 `draft`，恢复 `items`
  - `save`：调 `store.save()`，把 `draft` 提交；后端返回最新 items 覆盖 store
- 长按时迹/运动的"弹窗"逻辑：保留 `home/index.vue:382-388` 的 `handleQuickNavLongPress`，将判断改为"基于 path 匹配"（如 `path.includes('time-tracker')`）以兼容菜单改名

### 4.5 编辑弹窗（`QuickNavEditModal.vue`）

- 复用 AntD `Modal` + `Tree` / `Checkbox.Group`
- 树数据来源：`getCandidatesApi()`
- 已添加项禁用 + 显示"已添加"标签
- 上限 8 校验：`selected.length + draft.length >= 8` 时禁用勾选
- 提交：合并 `draft` 与新选 → 返回上层

### 4.6 `home/index.vue` 改造点

```diff
- import { WorkbenchQuickNav } from '@vben/common-ui';
+ import { useQuickNavStore } from '#/store/quick-nav';
+ import QuickNavSection from './components/QuickNavSection.vue';
+ import { onMounted } from 'vue';

+ const quickNavStore = useQuickNavStore();

```

模板中替换 `WorkbenchQuickNav` 为 `<QuickNavSection :items="quickNavStore.items" />`，并删除 331-368 行硬编码数组与 372-388 行 `navTo / handleQuickNavLongPress`（迁入 `QuickNavSection` 内部）。

### 4.7 移动端

- 桌面：编辑态用顶部操作栏
- 移动：编辑态用底部抽屉（AntD `Drawer`），单项操作改用 `SwipeAction` 横向滑动显示删除
- 拖拽：移动端用 `vue-draggable-plus`（已支持触屏），桌面端可换 `@vueuse/integrations` 的 useSortable

## 6. 数据流（关键时序）

### 6.1 用户首次进入首页（无历史布局）

```
1. home/index.vue onMounted
2. store.load()
3.   → GET /quick-nav/my     → [] (空数组)
4. items = []
5. 渲染空态卡片
```

### 6.2 用户添加并保存布局

```
1. 用户点空态卡 / 编辑按钮 → 打开 PickerModal
2. 用户勾选 N 项 → 点确认
3. 内部进入编辑态，draft 持有这 N 项
4. 用户点"保存"
5. store.save(draft)
6.   → POST /quick-nav/my {items:[...]} 
7.   ← 返回保存后的完整 items
8. items.value = response
9. 退出编辑态，渲染已保存布局
```

### 6.3 用户清空全部

```
1. 编辑态下点"清空全部" → 二次确认
2. store.clear()
3.   → POST /quick-nav/my {items:[]}
4. items.value = []
5. 退出编辑态，渲染空态卡片
```

### 6.4 候选池接口（按需）

```
- 进入 PickerModal 时 → GET /quick-nav/candidates
- 候选池按用户角色过滤；只返回叶子菜单
- 接口失败时 PickerModal 显示空列表 + 重试按钮
```

## 8. 性能与可观测

- 列表 `GET /quick-nav/my` 单用户规模（< 10 项）无需分页
- 候选池 `GET /quick-nav/candidates` 当前约 20+ 叶子菜单，可一次返回；超过 100 再考虑分页
- 加埋点：保存成功率、编辑态停留时长、常用候选 top 5
- 日志：`QuickNavService` 在 save 时打 INFO（含 userId + 数量），便于排查

## 9. 测试要点

### 9.1 单元测试

- `QuickNavService.saveMy`：
  - 空列表保存（清空场景）
  - 数量上限 8 校验
  - 不可访问菜单拒绝
  - `sortOrder` 重复拒绝

### 9.2 接口测试

- `GET /quick-nav/my` 未登录 → 401
- `GET /quick-nav/my` 用户未保存 → `200 []`
- `POST /quick-nav/my` 超过 8 项 → 400
- `POST /quick-nav/my` 包含无权限菜单 → 403
- `POST /quick-nav/my` 传 `items: []` → `200 []`（清空）
- 整块保存后 `GET /quick-nav/my` 顺序与提交一致

### 9.3 端到端

- **新用户首屏为空态卡片**（核心验收点）
- 空态卡片可点击 → 打开 PickerModal → 选 N 项 → 保存 → 渲染已保存布局
- 编辑 → 保存 → 刷新布局一致
- 切换账号 / 设备布局同步
- 暗色模式无硬编码颜色
- 移动端可用
- 编辑态下"清空全部"二次确认 → 保存为空 → 回到空态

## 10. 风险与后续

| 风险 | 缓解 |
|------|------|
| `sys_menu.meta` 字段被改后用户布局视觉错乱 | 渲染时取最新值 |
| 多设备并发保存 | v1 last-write-wins；后续加 `version` 列做乐观锁 |
| 候选池过大 | v1 不分页；后续超过 100 改成分页 + 搜索 |
| 用户自建外链诉求 | v1 不支持；后续可加 `is_external` 标记并允许用户填 url（但需评估安全） |
| 用户误清空全部 | 二次确认；后续可加"撤销最近一次保存"（基于 `update_time` 5 分钟内回滚） |
