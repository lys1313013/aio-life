# 用户反馈 — 需求方案

> 现状：系统无用户反馈入口，问题与改进建议散落在 IM / 邮件 / 口头，无法追踪、无法归因、无法闭环。
> 目标：提供用户反馈提交入口，用户只可见自己的反馈；管理员可见全部反馈并可回复、标记状态。反馈支持图片附件。反馈提交 / 追加评论时向指定管理员账号推送站内通知；管理员回复 / 状态变更时向反馈人推送站内通知。

---

## 一、范围

**In Scope**

- 用户提交反馈：标题、内容（富文本/Markdown 二选一）、类型（BUG / 建议 / 咨询 / 其他）、图片附件（最多 N 张）
- 用户查看自己的反馈列表与详情，可补充评论（追加反馈）
- 管理员查看全部反馈列表，可按状态、类型、时间、用户筛选
- 管理员可对反馈进行回复、状态流转（待处理 / 处理中 / 已解决 / 已关闭 / 已驳回）
- 图片走 MinIO，鉴权访问
- 站内消息通知：反馈提交 / 追加评论 → 通知指定管理员；管理员回复 / 状态变更 → 通知反馈人
- 通用系统配置表 `system_config`，管理员可在后台配置反馈通知接收人（指定管理员账号列表）

**Out of Scope**

- 用户间互相查看反馈
- 公开反馈 / 社区化投票 / 点赞
- 工单系统（分配、SLA、升级）
- 邮件推送（一期不做，但通知基础设施预留扩展点，后续可接入 `EmailNotificationSender`）

---

## 二、用户故事

1. **提交反馈**：用户填写标题、内容、类型，可选上传图片 → 提交 → 列表出现一条"待处理"。
2. **查看进度**：用户进入反馈中心，看到自己所有反馈及状态流转；点击查看详情与管理员回复。
3. **补充信息**：用户在已有反馈下追加评论（含图片），管理员侧可见新增条目。
4. **管理员处理**：管理员进入反馈管理页 → 筛选 → 查看详情 → 回复 → 变更状态。
5. **管理员批量**：管理员可批量关闭 / 批量标记。
6. **管理员收通知**：用户提交反馈或追加评论后，被配置为接收人的管理员账号收到站内通知，点击跳转到反馈详情。
7. **用户收通知**：管理员回复或变更状态后，反馈人收到站内通知，点击跳转到自己的反馈详情。
8. **配置通知接收人**：管理员在"系统配置"页面维护反馈通知接收人列表（从系统管理员账号中勾选）。

## 三、字段设计

### 3.1 主表 `feedback`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| user_id | BIGINT | 反馈人 |
| title | VARCHAR(200) | 标题 |
| content | TEXT | 内容（Markdown） |
| feedback_type | VARCHAR(32) | `BUG` / `SUGGESTION` / `QUESTION` / `OTHER` |
| status | VARCHAR(32) | `PENDING` / `PROCESSING` / `RESOLVED` / `CLOSED` / `REJECTED` |
| priority | VARCHAR(16) | `LOW` / `MEDIUM` / `HIGH`（预留，一期可不开放选择） |
| create_time / update_time | DATETIME | |
| is_deleted | TINYINT(1) | 逻辑删除 |

索引：`(user_id, create_time)`、`(status, create_time)`。

**附件处理**：不单独建表。附件复用全局 `file` 表，通过 `file.biz_type = 'feedback'` + `file.biz_id = feedback.id` 关联。

- 提交时：`FeedbackCreateRequest.fileIds: List<String>` 用于创建后调用 `IFileService.bindBizId(fileIds, "feedback", id)` 绑定
- 响应时：`FeedbackVO.files: List<FileVO>` 由 `IFileService.getByBiz("feedback", id)` 填充

### 3.2 评论/追加 `feedback_comment`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| feedback_id | BIGINT | |
| user_id | BIGINT | 评论人（用户或管理员） |
| content | TEXT | 评论正文（Markdown） |
| role_type | VARCHAR(16) | `USER` / `ADMIN` |
| create_time | DATETIME | |
| is_deleted | TINYINT(1) | |

**附件处理**：与主表同理。`file.biz_type = 'feedback_comment'` + `file.biz_id = comment.id`。

- 提交时：`FeedbackCommentCreateRequest.fileIds: List<String>` 用于评论创建后 `bindBizId`
- 响应时：`FeedbackCommentVO.files: List<FileVO>` 由 `getByBiz` 填充

### 3.3 对象模型（VO / Request）

| fileIds | List\<String\> | 否 | 上传后返回的 file_id 列表 |

**`FeedbackUpdateRequest`**（更新请求，一期暂不需要，反馈创建后不可编辑内容；仅状态变更由 admin 接口处理）

**`FeedbackVO`**（响应）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | |
| userId | Long | 反馈人 |
| userName | String | 反馈人姓名（关联查询） |
| title | String | |
| content | String | |
| feedbackType | String | |
| status | String | |
| priority | String | |
| files | List\<FileVO\> | 附件列表 |
| commentCount | Integer | 评论数 |
| createTime | String | |
| updateTime | String | |

**`FeedbackDetailVO extends FeedbackVO`**（详情响应，含评论时间线）

| 字段 | 类型 | 说明 |
|------|------|------|
| comments | List\<FeedbackCommentVO\> | 评论时间线（按时间正序） |

### 3.4 系统配置 `system_config`（通用 KV 配置表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| config_key | VARCHAR(128) | 配置键（唯一） |
| config_value | TEXT | 配置值（JSON 或纯文本） |
| config_type | VARCHAR(32) | `STRING` / `JSON` / `BOOLEAN` / `NUMBER`（前端渲染用） |
| description | VARCHAR(512) | 配置说明（前端展示） |
| update_user | BIGINT | 最后修改人 |
| update_time | DATETIME | |

唯一索引：`config_key`。

**反馈通知相关配置项**：

| config_key | config_value | 说明 |
|------|------|------|
| `feedback.notify_admin_ids` | `["1","3","5"]` | 接收反馈通知的管理员 user_id 列表（JSON 数组，ID 为 string） |

配置表设计为**通用 KV**，后续其他模块（邮件开关、注册开关、功能灰度等）复用同一张表，不重复建表。

### 3.5 通知复用

通知发送**不新建表**，直接复用现有基础设施：

- `AbstractNotificationSender` 抽象（`top.aiolife.record.notification`）
- `SystemNotificationSender`：写 `MessageEntity`，接收方进入消息中心即可看到
- `EmailNotificationSender`：发邮件（一期不调用，通道已就绪）

## 四、接口设计（草案）

**用户侧**（需登录，数据范围强制 `user_id = current`）

| 方法 | 路径 | Request | 响应 | 说明 |
|------|------|------|------|------|
| POST | `/feedback` | `FeedbackCreateRequest` | `FeedbackVO` | 提交反馈 |
| GET | `/feedback/my` | query params（status/type/分页） | `Page<FeedbackVO>` | 我的反馈列表 |
| GET | `/feedback/my/{id}` | - | `FeedbackDetailVO` | 我的反馈详情（含评论） |
| POST | `/feedback/{id}/comment` | `FeedbackCommentCreateRequest` | `FeedbackCommentVO` | 追加评论 |
| DELETE | `/feedback/{id}` | - | void | 撤销（仅 `PENDING`） |
| POST | `/feedback/upload-attachment` | `MultipartFile` + `bizType` | `FileVO` | 图片上传 |

**文件处理模式**（与 `HonorRecordController` 一致）：
- 上传：前端调 `/feedback/upload-attachment`，后端调 `fileService.uploadAndSave(file, bizType, bucket, objectName, 0)` 写入全局 `file` 表，`biz_type` 按参数传 `feedback` / `feedback_comment`
- 绑定：创建反馈 / 评论后，调 `fileService.bindBizId(fileIds, bizType, bizId)` 将文件与业务记录关联
- 查询：调 `fileService.getByBiz(bizType, bizId)` 填充 `files` 出参

**管理员侧**（需 admin 角色）

| 方法 | 路径 | Request | 响应 | 说明 |
|------|------|------|------|------|
| GET | `/feedback/admin/list` | query params（status/type/userId/时间范围/分页） | `Page<FeedbackVO>` | 全部反馈 |
| GET | `/feedback/admin/{id}` | - | `FeedbackDetailVO` | 详情 |
| POST | `/feedback/admin/{id}/reply` | `FeedbackCommentCreateRequest` | `FeedbackCommentVO` | 管理员回复 |
| PUT | `/feedback/admin/{id}/status` | `{ status: String }` | `FeedbackVO` | 状态变更 |
| POST | `/feedback/admin/batch` | `{ idList: List<Long>, action: String }` | void | 批量操作 |

**系统配置侧**（需 admin 角色）

| 方法 | 路径 | Request | 响应 | 说明 |
|------|------|------|------|------|
| GET | `/system-config/list` | query params（keyPrefix） | `List<SystemConfigVO>` | 配置列表 |
| GET | `/system-config/{key}` | - | `SystemConfigVO` | 单项配置 |
| PUT | `/system-config/{key}` | `SystemConfigUpdateRequest` | `SystemConfigVO` | 更新配置 |

数据隔离：用户侧 SQL 强制 `user_id = ?`；管理员侧无此限制。即便构造请求也无法越权。

## 五、UI 行为

### 5.1 用户 — 反馈中心入口

- 菜单位置：`我的` → `反馈中心`（与个人信息、修改密码同级）
- 入口图标：`mdi:message-alert-outline`

### 5.2 用户 — 反馈列表

- 顶部 Tab：全部 / 待处理 / 处理中 / 已解决 / 已关闭 / 已驳回
- 列表项卡片：标题 + 类型徽标 + 状态徽标 + 摘要（前 40 字） + 时间 + 评论数 + 附件缩略图数量
- 空态：`还没有反馈记录` + `[提交反馈]` 主按钮
- 浮动按钮：右下角 `+` 新建反馈

### 5.3 用户 — 提交 / 编辑反馈

弹窗（移动端全屏）：
- 标题（必填，≤200 字）
- 类型（单选，默认 `BUG`）
- 内容（必填，Markdown 编辑器，移动端降级为 textarea）
- 图片上传（≤9 张，单张 ≤5MB，支持 JPG/PNG/GIF/WEBP）
- 提交按钮，提交中 loading

### 5.4 用户 — 反馈详情

- 顶部：标题、类型、状态徽标、提交时间
- 中部：原始内容 + 附件九宫格
- 下部：评论时间线（按时间正序），区分用户/管理员气泡
- 底部：追加评论输入框（含图片上传）
- 仅 `PENDING` 状态显示"撤销反馈"按钮（需二次确认）

### 5.5 管理员 — 反馈管理

- 独立菜单 `系统管理` → `反馈管理`（`authority: ['admin']`）
- 顶部筛选：状态、类型、用户（模糊搜索）、时间范围
- 列表列：标题 / 用户 / 类型 / 状态 / 评论数 / 提交时间 / 最后更新 / 操作
- 操作列：查看详情 / 回复 / 变更状态
- 详情抽屉：右侧抽屉展示完整内容 + 时间线 + 回复框（与用户侧详情共用评论组件，但可改状态）

### 5.6 管理员 — 系统配置

- 菜单位置：`系统管理` → `系统配置`（`authority: ['admin']`）
- 入口图标：`mdi:cog-outline`
- 列表形式：配置项以分组卡片展示（一期仅"反馈通知"分组，后续按 config_key 前缀自动分组）
- 配置项编辑：
  - `STRING` / `NUMBER` → 输入框
  - `BOOLEAN` → Switch
  - `JSON`（如 `feedback.notify_admin_ids`） → 专用组件：从系统管理员列表中勾选，已勾选者展示姓名 + 头像 + 删除按钮；底部"添加"按钮弹出人员选择器
- 保存后即时生效，下次触发通知时读取最新配置
- 默认值：首次访问且 key 不存在时，`feedback.notify_admin_ids` 默认为空列表（不通知任何人）

## 六、边界

| 场景 | 行为 |
|------|------|
| 上传非图片 / 超大文件 | 前端拦截，提示"仅支持图片且单张不超过 5MB" |
| 上传数达 9 张上限 | "+"按钮禁用并提示 |
| 图片上传失败 | 单张红标 + 重试按钮，不阻塞其他张 |
| 撤销已撤销 / 已关闭的反馈 | 前端禁用撤销按钮；后端校验状态拒绝 |
| 用户越权查看他人反馈 | 后端强制 `user_id = current`，返回 404 |
| 用户构造路径查看管理员接口 | 角色鉴权拦截，返回 403 |
| 管理员回复自己关闭的反馈 | 允许（历史沟通可追溯），但不自动改状态 |
| 反馈被删除（逻辑删除） | 用户侧不再展示；管理员侧保留"已删除"态或直接不再展示（一期选择直接不展示） |
| 并发状态变更 | 乐观锁 / 状态前置校验，冲突返回最新状态 |
| 图片鉴权失效 | 复用现有 `fetchAuthImageUrl` 走后端签名 |
| 通知接收人未配置 | `feedback.notify_admin_ids` 为空列表 → 不发通知，不报错 |
| 通知接收人已离职 / 被禁用 | 后端发送前校验用户状态，已禁用/删除的用户跳过发送并记录日志 |
| 通知发送失败 | 调用 `SystemNotificationSender.send` 已做 try/catch，失败仅记日志不影响反馈提交主流程 |
| 同一反馈短时间多次追加评论 | 后端做去重（同用户 30s 内同内容不重复触发通知） |
| 管理员回复自己的反馈 | 不触发对自己的通知；如该管理员也是接收人，跳过本人 |
| 系统配置被普通用户访问 | 接口鉴权 403，前端无菜单 |

## 七、非功能

- **性能**：列表分页默认 20；附件查询走索引；图片缩略图按需生成（一期直接用原图，后续接入 MinIO 缩略 API）
- **审计**：状态变更记录到 `feedback_log`（可选，一期可不落地，仅评论留痕）
- **监控**：提交 / 回复接口打点；错误率告警

---

## 八、验收

- [ ] 用户可提交反馈（标题 + 类型 + 内容 + 图片）
- [ ] 用户在反馈中心只能看到自己的反馈，列表 / 详情均不可越权
- [ ] 用户可追加评论（含图片），时间线正确展示
- [ ] `PENDING` 状态可撤销，其他状态不可撤销
- [ ] 管理员可查看全部反馈，按状态 / 类型 / 用户 / 时间筛选
- [ ] 管理员可回复、可变更状态，变更即时反映在用户侧
- [ ] 图片上传、展示、删除（逻辑）全链路可用；鉴权正确
- [ ] 暗色模式、移动端可用；i18n 文案齐全
- [ ] 接口鉴权：普通用户调用 admin 接口返回 403
- [ ] 用户提交反馈 / 追加评论后，被配置为接收人的管理员在消息中心收到站内通知
- [ ] 管理员回复 / 变更状态后，反馈人在消息中心收到站内通知
- [ ] 通知接收人列表为空时，不报错、不发通知
- [ ] 通知接收人被禁用 / 删除时，跳过发送不报错
- [ ] 管理员在"系统配置"页面可勾选 / 取消勾选接收反馈通知的管理员，保存即时生效
- [ ] 通知不重复发送：同一用户 30s 内相同内容不重复触发
