# 生活足迹需求方案

日期：2026-10-21。状态：已实现，真实地图与部署联调待验证。

生活足迹记录「什么时间段，在什么具体地方生活」，用于回顾长期居住地点的变化。时间跨度通常为几个月或几年，地点精确到实际住所、小区、楼栋、宿舍等，支持在中国地图上查看并放大到具体位置。

界面采用简洁方案：地图为主，点选后展示时间、地点和备注。Web 与移动端使用相同的业务字段和交互规则。

## 一 功能范围

首期提供记录新增、编辑、删除，中国地图总览，地图缩放与拖动，具体地点选择，以及地址搜索和解析。

本功能独立于[时迹](时迹需求方案.md)。时迹记录日常时间分配，生活足迹记录长期生活地点。首期不增加生活经历、阶段名称、分类标签、照片、停留时长统计，也不采集实时定位或后台 GPS 轨迹。地点由用户主动录入，不根据居住天数自动判断是否属于一段生活记录。

建议入口为 Web「记录 → 生活足迹」、移动端「全部 → 记录 → 生活足迹」，随业务菜单统一提供图标与颜色。

## 二 录入字段

| 字段 | 是否必填 | 录入规则 |
| --- | --- | --- |
| 开始时间 | 是 | 精确到日，格式 `YYYY-MM-DD`，例如 `2016-09-01` |
| 结束时间 | 是，与至今二选一 | 精确到日；选择「至今」后不填写结束日期 |
| 地点 | 是 | 输入地址或地点名称后选择候选；也可直接地图选点。地点名称允许修改，如「老家」「大学宿舍」 |
| 地址 | 否 | 搜索或解析后自动带出，允许补充街道、小区、楼栋、单元和房号 |
| 备注 | 否 | 自由文本，记录需要补充的信息 |

地图位置是地点的一部分，必须有用户确认的经纬度才能完成保存。界面不要求用户手填或查看经纬度。地点输入同时承担搜索和名称编辑功能，不额外设置重复的「搜索地点」「地点名称」输入框。

楼栋、单元和房号通过地址补充，不承诺地图服务能为每个房间返回独立坐标。多个住所可能落在相同建筑位置，仍可分别保存。

## 三 时间与记录规则

1. 开始、结束均填写完整日期，精确到日；不支持只填写年份或年月，不设置日期精度字段。数据库使用 `DATE`，接口使用 `YYYY-MM-DD` 字符串。
2. 结束日期不能早于开始日期，同日开始和结束允许保存；校验真实日历日期，包括闰年。
3. 开始和实际结束日期不能晚于今天（北京时间）；“至今”保存为结束日期 `9999-12-31`，界面仍显示“至今”。
4. 记录之间允许空档和时间重叠，不强制连续，也不强制只能有一个「至今」地点，以兼容双城生活等情况。
5. 搬离后又回到同一地点，新增一条时间段记录，保留之前的记录。同小区、同楼栋内搬家也可分别记录。
6. 地点、地址和坐标保留本条记录的快照。修改一条记录不会批量改写其他历史记录，地图地点改名也不自动覆盖用户填写的名称。

## 四 地图展示

### 全国总览

- 首次进入展示中国地图及已有地点标记，不默认展开详情面板。无记录时保持中国地图，提供新增入口。
- 同一城市或屏幕上过近的标记可以聚合，聚合数字表示记录条数。放大后逐步展开，避免文字和标记互相遮挡。
- 点击城市聚合点，缩放到能容纳该组地点的范围；点击具体地点，显示对应记录。一次聚合不能跳过其他记录直接选定某一住所。
- 聚合仅影响地图展示，不合并业务记录；同一位置有多条记录时，在紧凑列表中展示各自时间段，供用户选择。

### 缩放与位置精度

- Web 支持滚轮缩放、拖动、加减按钮；移动端支持双指缩放、拖动、加减按钮。
- 地图可从全国逐步放大到城市、街道、建筑附近。需要加载相应层级的真实底图，不能仅放大省界图来代替街区地图。
- 提供一个返回全国视图的入口，避免重复放置相同操作。查看、选择、编辑地点后尽量保留当前视野，返回全国由用户主动触发。
- 搜索命中后自动定位到结果附近，允许点选或移动标记微调。具体地址文本与地图标记共同表达地点精度。
- 省界、街道和标记采用适应主题的颜色；用户记录的标记保持突出，不为每条记录分配装饰色。

## 五 页面与交互

### Web

页面只保留「生活足迹」标题、新增图标、左侧记录列表和右侧地图。列表按开始时间升序排列，每条默认显示时间段和地点名称；时间相同时按稳定顺序展示。

点击列表记录或地图地点后，地图定位到对应位置，并显示一块紧凑详情：地点名称、时间段、地址、备注。备注为空时不显示备注行。详情提供编辑和关闭图标，删除入口放在编辑状态内，避免常驻过多操作。

平板宽度下调整列表与地图比例；空间不足时允许收起列表，不能把地图挤成无法操作的窄栏。

### 移动端

默认展示标题、新增入口和尽可能完整的地图，不常驻桌面侧栏或统计卡片。点选具体地点后，底部显示紧凑详情，保留足够地图操作空间；长地址和长备注可展开查看，不能遮挡全部地图或直接裁掉内容。

查看聚合点时先选择其中的记录，再展示该条详情。新增、编辑保持相同字段顺序：时间、地点及小地图、地址、备注、保存。输入框宽度和键盘弹起后的操作区域应能正常使用。

### 新增与编辑

1. 点击新增，填写开始、结束或「至今」。新增不默认提交某个示例地点或上次查看的地点，保存前必须完成位置确认。
2. 输入地点名称或地址，选择候选，或使用地图选点。地图定位到所选位置，名称、地址自动填充并允许修改。
3. 补充地址和备注，保存成功后局部更新记录列表与地图标记，定位到本条记录。
4. 编辑回填原有内容和坐标。更换实际地点或用新地址重新解析时，必须重新确认位置，未完成的搜索不能替换原坐标；仅修改显示名称或补充楼栋、房号不自动改动坐标。
5. 保存失败保留输入和选点；取消编辑不修改原记录。删除在触发按钮旁确认，成功后只更新相关记录、标记与详情。

上下居中的编辑弹窗、图标按钮的可访问名称、局部 loading、深浅主题和加载时的布局稳定，遵循主仓库及各端规范。

## 六 地址解析与百度地图方案

拟采用百度地图提供搜索、地址解析和地图展示能力。输入地址获取经纬度有两条路径：地点名称优先搜索候选，完整地址可以直接进行地理编码。结果均需在地图上由用户确认。

| 用户操作 | 使用的能力 | 产品行为 |
| --- | --- | --- |
| 输入地点名称或部分地址 | 地点输入提示、地点检索 | 展示名称及所在城市、地址，区分同名地点；用户选择后获取可用坐标 |
| 输入完整地址并发起解析 | 地理编码 | 把地址转换为经纬度并展示标记；结果只到城市、道路等范围时提示补充地址或调整位置 |
| 地图选点或微调标记 | 地图选点，可配合逆地理编码 | 直接获得选点坐标；可用地址描述自动带出，保留用户手填的楼栋、房号和自定义名称 |

地点搜索、地理编码和逆地理编码由后端统一适配第三方服务，同时校验第三方状态码和有效坐标，不能仅凭 HTTP 200 判断解析成功。搜索使用防抖及请求序号，用户继续输入、切换候选、选点或关闭表单后，旧响应不能覆盖新状态。地图标记微调结束后再解析地址，不在每个拖动事件中请求。

调用失败、超时、无结果或额度不足时，在受影响区域给出重试；保留表单、已有候选和选点。搜索失败仍允许地图选点；地图本身不可用且用户尚未确认位置时，保留输入并等待恢复，不保存伪造坐标。已有记录仅编辑时间或备注时，不要求重新调用地理编码。

百度地理编码可返回 `BD09` 经纬度。业务记录必须同时保存坐标系，底图与标记使用匹配的坐标系；跨供应商地图显示前进行明确转换，禁止把百度、国测局、GPS 坐标混用。浏览器地图配置与服务端调用配置分开管理，服务端密钥通过环境变量注入，不下发服务端密钥或提交凭据。

Web、H5、微信小程序和 App 的地图组件能力需要分别验证，不能把 Web 的百度地图方案直接视为所有终端已支持。各端可用地图适配、坐标转换方案，以及服务权限、调用额度与费用，应在接入前确定。

接口依据：[百度地理编码](https://lbsyun.baidu.com/docs/webapi?title=geocoding%2Fguide%2Fwebservice-geocoding-base)、[地点检索及输入提示](https://lbsyun.baidu.com/docs/webapi?title=placev3%2Fguide%2Fwebservice-placeapiV3%2FinterfaceDocumentV3)、[逆地理编码](https://lbsyun.baidu.com/docs/webapi?title=reverse_geocoding%2Fguide%2Fwebservice-geocoding-abroad-base)。

## 七 数据与接口约束

每条记录至少保存用户归属、起止日期、地点名称、地址、经纬度、坐标系和备注。可附带地图供应商及地点标识，用于结果追溯，不依赖每次打开页面重新搜索地址。

- 完整日期必须能往返保存，不补齐或截断。结束日期必填；选择“至今”时提交 `9999-12-31`，不使用 NULL 或单独状态字段。
- 经度、纬度在接口中为数值，ID 为字符串；所有接口沿用 `{ code: 0, message: null, data: ... }` 契约。
- 记录列表与地图标记使用同一批有效记录。列表若分页，地图应独立取得完整标记或覆盖当前视野的聚合结果，不能只画列表第一页。
- 记录增删改查、搜索及地图数据读取均校验登录态；服务端按当前用户隔离，禁止客户端指定他人身份。
- 保存期间禁用按钮并拦截重复点击；新增接口不承诺请求重放幂等，网络结果不确定时先重新读取确认。暂不使用乐观锁，同一账号多端编辑以最后一次成功保存为准；记录已删除或保存失败时保留本地输入并明确提示。
- 首期仅本人可见，不提供公开分享、持续定位或他人位置查询。时间与备注不发送给地图供应商。

## 九 验收要点

| 场景 | 验收结果 |
| --- | --- |
| 录入与修改 | 上述字段及位置确认可完成保存；地址、备注可为空，失败保留输入 |
| 日期规则 | 仅接受完整日期；拒绝年份、年月、非法日期、非“至今”未来日期和结束早于开始；同日、「至今」、跨年、重叠和空档符合规则 |
| 全国与街区 | 默认中国地图，可缩放和拖动至具体地点；街区底图不是省界图放大效果 |
| 聚合与重复地点 | 城市聚合能展开全部记录，同一坐标多时间段可选择，不丢记录、不错误合并住所 |
| 搜索与解析 | 同名候选可区分，低精度结果可纠正；无结果、失败、旧响应和手动微调均不覆盖新选择 |
| 坐标一致性 | Web、H5 及目标原生地图上，同一地点没有因坐标系混用而产生偏移 |
| 简洁与可用性 | 首屏无多余统计和常驻详情；图标有可访问名称，手机、平板、桌面及深浅主题均可操作 |
| 加载与异常 | 地图、搜索、保存分别反馈 loading；刷新保留已有内容，长地址、长备注及重试不导致异常挤压或裁切 |
| 数据完整与隔离 | 地图不因列表分页漏点；增删改局部更新，跨用户访问被拒绝，已删除记录不能再编辑 |

## 十 实现约定与验证（2026-10-21）

- Web 入口 `/record/life-footprints`，移动端入口 `/pages/life-footprints/index`；通过共用菜单启用，移动端地图与服务放入独立分包。
- 记录固定保存 `GCJ02` 坐标，百度检索和解析显式要求 `ret_coordtype=gcj02ll`；Web/H5 使用百度 JSAPI 4.0 的 GCJ02 模式，微信及 App 使用原生 `map`。不进行未经标注的坐标系混用。全国检索采用明确支持「全国」的地点检索 2.0，指定区域时采用区域检索 3.0。
- 手机普通点直径 8px、选中点 10px、聚合点 18px；透明点击区域 44px。原生端图片也保持相同比例，不把点击区域画成大圆点。
