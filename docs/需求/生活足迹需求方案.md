# 生活足迹需求方案

日期：2026-10-21。状态：已实现，真实地图与部署联调待验证。

生活足迹记录「什么时间段，在什么具体地方生活」，用于回顾长期居住地点的变化。时间跨度通常为几个月或几年，地点精确到实际住所、小区、楼栋、宿舍等，支持在中国地图上查看并放大到具体位置。

界面采用简洁方案：地图为主，点选后展示时间、地点和备注。Web 与移动端使用相同的业务字段和交互规则。

## 一 功能范围

首期提供记录新增、编辑、删除，中国地图总览，地图缩放与拖动，具体地点选择，以及地址搜索和解析。

本功能独立于[时迹](时迹需求方案.md)。时迹记录日常时间分配，生活足迹记录长期生活地点。首期不增加生活经历、阶段名称、分类标签、照片、停留时长统计，也不采集实时定位或后台 GPS 轨迹。地点由用户主动录入，不根据居住天数自动判断是否属于一段生活记录。

建议入口为 Web「记录 → 生活足迹」、移动端「全部 → 记录 → 生活足迹」，随业务菜单统一提供图标与颜色。

## 二 录入字段

| 字段 | 是否必填 | 录入规则 |
| --- | --- | --- |
| 开始时间 | 是 | 精确到日，格式 `YYYY-MM-DD`，例如 `2016-09-01` |
| 结束时间 | 是，与至今二选一 | 精确到日；选择「至今」后不填写结束日期 |
| 地点 | 是 | 输入地址或地点名称后选择候选；也可直接地图选点。地点名称允许修改，如「老家」「大学宿舍」 |
| 地址 | 否 | 搜索或解析后自动带出，允许补充街道、小区、楼栋、单元和房号 |
| 备注 | 否 | 自由文本，记录需要补充的信息 |

地图位置是地点的一部分，必须有用户确认的经纬度才能完成保存。界面不要求用户手填或查看经纬度。地点输入同时承担搜索和名称编辑功能，不额外设置重复的「搜索地点」「地点名称」输入框。

楼栋、单元和房号通过地址补充，不承诺地图服务能为每个房间返回独立坐标。多个住所可能落在相同建筑位置，仍可分别保存。

## 三 时间与记录规则

1. 开始、结束均填写完整日期，精确到日；不支持只填写年份或年月，不设置日期精度字段。数据库使用 `DATE`，接口使用 `YYYY-MM-DD` 字符串。
2. 结束日期不能早于开始日期，同日开始和结束允许保存；校验真实日历日期，包括闰年。
3. 开始和实际结束日期不能晚于今天（北京时间）；“至今”保存为结束日期 `9999-12-31`，界面仍显示“至今”。
4. 记录之间允许空档和时间重叠，不强制连续，也不强制只能有一个「至今」地点，以兼容双城生活等情况。
5. 搬离后又回到同一地点，新增一条时间段记录，保留之前的记录。同小区、同楼栋内搬家也可分别记录。
6. 地点、地址和坐标保留本条记录的快照。修改一条记录不会批量改写其他历史记录，地图地点改名也不自动覆盖用户填写的名称。

## 四 地图展示

### 全国总览

- 首次进入展示中国地图及已有地点标记，不默认展开详情面板。无记录时保持中国地图，提供新增入口。
- 同一城市或屏幕上过近的标记可以聚合，聚合数字表示记录条数。放大后逐步展开，避免文字和标记互相遮挡。
- 点击城市聚合点，缩放到能容纳该组地点的范围；点击具体地点，显示对应记录。一次聚合不能跳过其他记录直接选定某一住所。
- 聚合仅影响地图展示，不合并业务记录；同一位置有多条记录时，在紧凑列表中展示各自时间段，供用户选择。

### 缩放与位置精度

- Web 支持滚轮缩放、拖动、加减按钮；移动端支持双指缩放、拖动、加减按钮。
- 地图可从全国逐步放大到城市、街道、建筑附近。需要加载相应层级的真实底图，不能仅放大省界图来代替街区地图。
- 提供一个返回全国视图的入口，避免重复放置相同操作。查看、选择、编辑地点后尽量保留当前视野，返回全国由用户主动触发。
- 搜索命中后自动定位到结果附近，允许点选或移动标记微调。具体地址文本与地图标记共同表达地点精度。
- 省界、街道和标记采用适应主题的颜色；用户记录的标记保持突出，不为每条记录分配装饰色。

## 五 页面与交互

### Web

页面保留「生活足迹」标题、新增图标、左侧时间段列表和右侧地图。前端将同一用户起止日期完全相同的记录归为一组，显示共用时间段，组内地点分别按行展示，不拼接名称；仅时间重叠不归组。列表按开始时间升序排列，组内按记录 ID 稳定排序。数据库仍是一条地点明细一行，不新增时间段主表或分组字段。

时间段旁提供编辑图标，可从左侧直接打开该组编辑弹窗。点击日期定位整组，点击单个地点定位该条；地图点选与左侧高亮联动，主地图不再覆盖重复详情面板。备注在对应地点下展示，为空时不占行；删除入口保留在编辑状态内。

平板宽度下调整列表与地图比例；空间不足时允许收起列表，不能把地图挤成无法操作的窄栏。

### 移动端

默认展示标题、新增入口和尽可能完整的地图，不常驻桌面侧栏或统计卡片。点选具体地点后，底部显示紧凑详情，保留足够地图操作空间；长地址和长备注可展开查看，不能遮挡全部地图或直接裁掉内容。

查看聚合点时先选择其中的记录，再展示该条详情。新增、编辑保持相同字段顺序：时间、地点及小地图、地址、备注、保存。输入框宽度和键盘弹起后的操作区域应能正常使用。

### Web 时间段与多明细编辑

- 主页面左侧每个时间段内按行展示各地点及备注，日期旁提供直接编辑入口；点击日期定位整组，点击地点定位单条。主地图不再覆盖重复的详情面板，点击聚合点在左侧高亮对应明细。
- 新增、编辑使用同一弹窗：顶部填写共用起止日期，左侧为明细导航，右侧为共享地图，地图下方编辑当前明细的地区、地点与备注。
- 编辑已有记录时载入所有起止日期相同的明细；每条明细保留独立 ID、地区、地点、坐标、地址快照和备注。添加空白明细不自动继承已有地点或坐标。
- 地图同时展示当前时间段已选位置的明细，编号对应导航；选中一条明细不会隐藏其他标记。近距离标记聚合，点击后选择具体明细，同位置多条备注分别保留。
- 地图选点是显式操作，只调整当前明细；切换明细时取消旧搜索与地址回填，旧响应不得覆盖新选中明细。查看全部地点恢复当前组的整体视野。
- 修改公共日期会同步写入本次提交的全部保留明细。日期修改后与另一组完全相同，前端重新计算并合组；不改写另一组原有的地点、备注或坐标。
- 新增、编辑、删除先暂存在弹窗内，点击“保存全部”一次提交；删除最后一条表示保存后删除该组当前记录。取消不写入。失败保留输入；网络中断或服务端错误导致结果不确定时禁止直接重放新增请求，需重新读取确认。
- `POST /life-footprints/batch` 接收 `items`（每条含可空 ID 与完整现有保存字段）和 `deletedIds`，每类最多 200 条。服务端校验日期一致、重复/交叉 ID、用户归属、逻辑删除状态和嵌套字段；只删除显式提交的 ID，不按日期或未提交记录推断删除。
- 一次事务完成全部新增、更新、逻辑删除，任何失败全部回滚；返回本次保存的明细列表，前端局部替换，不重载全页。旧单条接口保留，移动端仍可兼容原有录入方式；自动分组不提供持久化组身份。

### 单条录入基础规则

1. 点击新增，填写开始、结束或「至今」。新增不默认提交某个示例地点或上次查看的地点，保存前必须完成位置确认。
2. 输入地点名称或地址，选择候选，或使用地图选点。地图定位到所选位置，名称、地址自动填充并允许修改。
3. 补充地址和备注，保存成功后局部更新记录列表与地图标记，定位到本条记录。
4. 编辑回填原有内容和坐标。更换实际地点或用新地址重新解析时，必须重新确认位置，未完成的搜索不能替换原坐标；仅修改显示名称或补充楼栋、房号不自动改动坐标。
5. 保存失败保留输入和选点；取消编辑不修改原记录。删除在触发按钮旁确认，成功后只更新相关记录、标记与详情。

上下居中的编辑弹窗、图标按钮的可访问名称、局部 loading、深浅主题和加载时的布局稳定，遵循主仓库及各端规范。

## 六 地址解析与地图展示方案

后台查询采用百度优先、配额耗尽后腾讯备用；Web 主地图及新增、编辑弹窗统一采用腾讯 GL 白浅底图和后端 Key 代理，移动端 H5 保留开源组件与可替换底图。输入地址获取经纬度有两条路径：地点名称优先搜索候选，完整地址可以直接进行地理编码。结果均需在地图上由用户确认。

| 用户操作 | 使用的能力 | 产品行为 |
| --- | --- | --- |
| 输入地点名称或部分地址 | 地点输入提示、地点检索 | 展示名称及所在城市、地址，区分同名地点；用户选择后获取可用坐标 |
| 输入完整地址并发起解析 | 地理编码 | 把地址转换为经纬度并展示标记；结果只到城市、道路等范围时提示补充地址或调整位置 |
| 地图选点或微调标记 | 地图选点，可配合逆地理编码 | 直接获得选点坐标；可用地址描述自动带出，保留用户手填的楼栋、房号和自定义名称 |

地点搜索、地理编码和逆地理编码由后端统一适配第三方服务，同时校验第三方状态码和有效坐标，不能仅凭 HTTP 200 判断解析成功。搜索使用防抖及请求序号，用户继续输入、切换候选、选点或关闭表单后，旧响应不能覆盖新状态。地图标记微调结束后再解析地址，不在每个拖动事件中请求。

调用失败、超时、无结果或额度不足时，在受影响区域给出重试；保留表单、已有候选和选点。搜索失败仍允许地图选点；地图本身不可用且用户尚未确认位置时，保留输入并等待恢复，不保存伪造坐标。已有记录仅编辑时间或备注时，不要求重新调用地理编码。

业务记录与地图查询结果统一使用 `GCJ02`，百度请求显式要求返回 GCJ02。Web 直接显示与提交 GCJ02，H5 仅在 WGS84 瓦片展示与选点边界转换，禁止混入 BD09/WGS84 原值。腾讯展示 Key 与搜索解析 Key 独立加密存储，仅后端使用，不下发任何 Key 或密文。

Web、H5、微信小程序和 App 的地图组件能力需要分别验证，不能把 Web 的地图方案直接视为所有终端已支持。各端可用地图适配、坐标转换方案，以及服务权限、调用额度与费用，应在接入前确定。

接口依据：[腾讯关键词输入提示](https://lbs.qq.com/service/webService/webServiceGuide/webServiceSuggestion)、[地址解析](https://lbs.qq.com/service/webService/webServiceGuide/webServiceGeocoder)、[逆地址解析](https://lbs.qq.com/service/webService/webServiceGuide/webServiceGcoder)。

## 七 数据与接口约束

每条记录至少保存用户归属、起止日期、地点名称、地址、经纬度、坐标系和备注。可附带地图供应商及地点标识，用于结果追溯，不依赖每次打开页面重新搜索地址。

- 完整日期必须能往返保存，不补齐或截断。结束日期必填；选择“至今”时提交 `9999-12-31`，不使用 NULL 或单独状态字段。
- 经度、纬度在接口中为数值，ID 为字符串；所有接口沿用 `{ code: 0, message: null, data: ... }` 契约。
- 记录列表与地图标记使用同一批有效记录。列表若分页，地图应独立取得完整标记或覆盖当前视野的聚合结果，不能只画列表第一页。
- 记录增删改查、搜索及地图数据读取均校验登录态；服务端按当前用户隔离，禁止客户端指定他人身份。
- 保存期间禁用按钮并拦截重复点击；新增接口不承诺请求重放幂等，网络结果不确定时先重新读取确认。暂不使用乐观锁，同一账号多端编辑以最后一次成功保存为准；记录已删除或保存失败时保留本地输入并明确提示。
- 首期仅本人可见，不提供公开分享、持续定位或他人位置查询。时间与备注不发送给地图供应商。

| 场景 | 验收结果 |

| 数据完整与隔离 | 地图不因列表分页漏点；增删改局部更新，跨用户访问被拒绝，已删除记录不能再编辑 |

## 十 实现约定与验证（2026-10-21）

- Web 入口 `/record/life-footprints`，移动端入口 `/pages/life-footprints/index`；通过共用菜单启用，移动端地图与服务放入独立分包。
- 记录固定保存 `GCJ02` 坐标，百度检索和解析显式要求 `ret_coordtype=gcj02ll`；Web/H5 使用随前端打包的 Leaflet 和可替换 XYZ 底图，展示与选点按底图坐标系做 WGS84/GCJ02 转换；微信及 App 使用原生 `map`。不进行未经标注的坐标系混用。全国检索采用明确支持「全国」的地点检索 2.0，指定区域时采用区域检索 3.0。
- 手机普通点直径 8px、选中点 10px、聚合点 18px；透明点击区域 44px。原生端图片也保持相同比例，不把点击区域画成大圆点。
- 新增不携带幂等键，增删改不携带 `version`，暂不使用乐观锁；`update_time` 仅记录最后更新时间，不作为并发校验条件。保存失败时保留表单，地图读取本人全量记录。
- 管理员在「系统配置 → 生活足迹地图」填写百度服务端 AK 和底图设置，保存至现有 `system_config` 表的 `footprints.baidu` JSON 项并实时生效，首次保存自动创建配置记录，无需新增表。服务端 AK 加密存储、不回显，留空保留、填写替换、显式清除；加密主密钥沿用部署侧 `AIO_LIFE_NOTIFICATION_ENCRYPTION_KEY`。后端仅保留 `AIO_LIFE_MAP_TIMEOUT_MS`（默认 5000）作为地图超时环境变量，不再读取两类 AK 环境变量，Web/H5 不需要浏览器 AK；详情及申请流程见后端 README「生活足迹」。

### Web 腾讯地图官方代理（2026-10-22）

配置读取、SDK 加载、本站会话校验及后端注入 Key 的完整时序见[腾讯地图代理接入技术文档](../../aio-life-server/docs/腾讯地图代理接入.md)。

- 按[腾讯 GL 官方代理文档](https://lbs.qq.com/webApi/javascriptGL/glGuide/glKeyDelegate)设置 `window._TMapSecurityConfig.serviceHost`，SDK 加载 URL 不含 Key。代理随现有 `/api` 反向代理访问后端，无需在 Nginx 或前端环境变量中复制 Key；沿用 `footprints.tencent` 的历史加密配置，无需数据库迁移或重新填写。
- 代理地址为 `/api/life-footprints/map/tencent-proxy`，仅开放统计、`/checkKey` 与 `/oversea` 三个地图必需的 GET 路由，固定转发到腾讯官方上游；不开放任意 URL 和 `/service` WebService 转发。地点搜索与地址解析继续走现有百度后端适配。
- 浏览器与 API 必须同源。读取地图配置后，后端签发仅限代理路径的 HttpOnly、SameSite=Strict Cookie，HTTPS 下带 Secure；Cookie 以 AES-GCM 加密绑定原登录会话，最长一天，过期后重新加载足迹页面。SDK 自动携带 Cookie，代理仍经过现有登录、账号状态及二级锁检查，退出或撤销原会话后不能继续转发。Cookie 和 Authorization 不会发送到腾讯。
- 单实例限制每用户每分钟 240 次、全局每分钟 2400 次及 16 个并发，上游连接超时 3 秒、总请求超时 8 秒，不跟随重定向；多实例总额度需按部署规模另行限制。响应禁止缓存，不传回上游 Cookie/重定向地址，响应中可能回显的 Key 会被去除。保留腾讯 JSON/JSONP 业务状态供 SDK 判断，HTTP 200 不代表鉴权成功。
- 管理界面的配置字段保持兼容，只提交新 Key 时会发送给自有后端保存；地图配置及地图运行请求不向浏览器下发 Key。已经暴露过的 Key 可在控制台轮换，再通过系统配置保存；迁移代理本身不会撤销历史 Key。

### 后台查询双供应商（2026-10-22）

此节替代前述“查询只走腾讯、不使用百度 AK”的阶段说明。

- 用 `FootprintMapProvider` 抽象地点搜索、地址解析、逆地址解析；百度与腾讯独立实现，公共 HTTP 校验与坐标映射复用抽象类，供应商选择由统一查询入口负责。
- 查询默认先调用百度；配额耗尽（业务状态 4、301、302）、并发限制（401、402）或 HTTP 429 时，同一次请求调用腾讯一次。额度耗尽按 AK 指纹及实际 API 路径记入 Redis，跨实例共享，后续命中直接跳过百度；日额度缓存到北京时间次日零点，永久配额缓存 24 小时后重新探测。并发限制只切换当次，不记为额度耗尽。鉴权失败、网络超时、无结果不触发切换；腾讯失败不循环重试。
- 百度 AK 未配置时可直接使用腾讯；两家均未配置时关闭搜索，保留地图显示和手工选点。`footprints.baidu` 恢复 AK 和查询超时设置，腾讯仍拆分展示和查询 Key，凭据均不返回前端。
- 该机制识别厂商配额耗尽响应，不能从成功响应判断是否已经消耗付费流量；不承诺免费余额精确计数或自动阻断付费额度。
- Redis 不可读时直接使用腾讯；状态写入失败也允许本次备用。更换 AK 不受旧状态影响，原 AK 在途错误不会污染新 AK；状态过期后自动重新探测，不保证厂商届时已恢复。
- 三类查询统一 GCJ02，API 契约与腾讯底图代理不变。详细切换规则与时序见[技术文档](../../aio-life-server/docs/腾讯地图代理接入.md#查询接口与供应商切换)。
