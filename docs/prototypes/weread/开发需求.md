# AIO Life 阅读模块开发需求（原型确认稿）

## 范围
参考微痕的信息组织方式，以 AIO Life 风格制作本地 HTML 原型。本次仅连接微信读书，展示真实阅读看板、书架、笔记，不修改正式前后端代码，不写入微信读书。

## 1. 阅读看板
- 周、月、年、累计四种统计周期。
- 指标：阅读时长、阅读天数、日均阅读、已读完本数。
- 阅读时长趋势：按接口返回的时间粒度展示，悬停查看值。
- 阅读时长 Top 书籍：封面、书名、时长、相对长度。
- 最近阅读：从书架最近阅读时间排序，点击查看书籍详情。
- 后续待确认：历史年份切换、热力图、阅读目标、作者/分类偏好。当前账号统计接口未返回稳定的偏好字段，原型不生成这些内容。

## 2. 书架
- 封面网格：书名、作者、已读完/未读完、划线/点评数量。
- 搜索书名、作者；筛选全部、已读完、未读完、有笔记；最近阅读和书名排序。
- 有笔记的书可从笔记本接口展示进度；其余打开详情后获取。
- 详情弹窗：阅读进度、累计阅读时长、最近阅读时间、阅读状态；跳转笔记或微信读书（有返回链接时）。
- 图书数只统计 books，不将有声专辑或文章收藏计入图书。
- 不用“未读完”推断“在读”：微信字段不足以可靠区分未开始、在读和搁置。

## 3. 笔记
- 笔记本列表：书籍封面、书名、划线数和点评数；搜索书名和作者。
- 详情：划线、想法、书评三个标签。
- 划线展示章节、原文、创建时间；按章节及 range 精确关联想法。
- 想法/书评展示引用原文、个人内容、创建时间。
- 支持本书内容搜索、复制原文与想法。
- 笔记本及点评按接口游标读取全部分页；分页异常明确报错。
- 后续待确认：跨书全文搜索、图片/PDF 导出、独立书评墙。

## 4. 数据口径与交互
- 总阅读时长使用 totalReadTime，单位为秒；界面转换成小时或分钟。
- 日均使用 dayAverageReadTime，按微信读书自然日口径，界面标明分母。
- 读完数使用 readStat 中 stat=读完 的 counts，不以书架 finishReading 累加替代周期统计。
- noteCount 对应笔记本划线数量，本次通过 bookmarklist 返回数量交叉验证；reviewCount 为点评数量，进入详情后再区分想法与书评。
- 阅读进度为 0–100 的百分数；不乘以 100。
- 不把电子书出版状态 finished 当作个人读完状态。
- 缺失数据显示“暂无数据/—”；真实 0 正常展示为 0。
- 所有数据请求有加载状态；错误可重试；支持空状态、暗色和移动布局。
- 本原型只展示微信数据，不合并手动时迹、不更新本地阅读状态。

## 5. 本地运行和凭证
- 页面：index.html，纯 HTML/CSS/JavaScript，无安装依赖。
- 本地代理：Python 标准库 server.py，用于跨域调用与保管凭证，仅监听 127.0.0.1。
- 运行：在本目录执行 python3 server.py，再打开 http://127.0.0.1:8765。
- Key 从本机 .env 或 WEREAD_API_KEY 环境变量读取，不嵌入 HTML，不返回浏览器，不提交 Git。
- .env 权限为 600，已受根目录 .gitignore 排除；服务不会通过文件路由暴露配置。
- 阅读响应仅缓存在进程内 5 分钟；刷新按钮强制重新读取，不将阅读数据保存到磁盘。
- 网络请求：数据与 Key 发往微信读书官方网关，封面从接口提供的 HTTPS 地址加载。
- 双击 HTML 可看到启动提示，真实数据功能需本地服务运行。

## 待确认的正式开发范围
建议首版采用上述三个页面和只读同步；需要进一步确认：
1. 是否将微信图书自动关联到 AIO Life 现有阅读记录，或由用户手动绑定？
2. 正式版是否按日保存阅读快照，支持长期历史回顾？
3. 书评、跨书全文搜索、导出是否纳入首版？当前原型已有单书书评与本书搜索。
