# 时迹二级分类实现

## 规则

- 最多两级；一级和二级均可直接录入，一条时迹仍只保存一个 `category_id`。
- 公共分类与个人分类沿用同一分类表。公共分类的个人覆盖仍通过 `template_id` 表示，对外 ID 始终为公共分类 ID。
- 一级分类筛选包含自身和二级分类。默认图表按一级汇总，选择分类后显示直接记录和子级明细，父子同时选中不重复统计。
- 移动分类后，历史统计按当前分类树重新归集，不保存归属快照。
- 隐藏/停用父分类会使其二级分类不可用于新增录入，但保留历史显示；恢复父级不会覆盖子级独立停用设置。
- 有子分类或有效时迹记录时拒绝删除。个人分类可隐藏和恢复，公共分类由管理员停用。

## 数据库与上线顺序

先执行后端 `sql/1_init_table/2026-09-27_time_category_parent.sql`，再发布后端，最后发布前端。

分类表新增 `parent_id bigint NULL`：公共分类和个人原创分类的根节点写 `0`；个人覆盖记录写 `NULL` 表示继承公共归属，写 `0` 表示明确移到一级。原有业务非空字段不变；`time_record` 不变。

迁移将旧公共/原创分类设为根级，旧覆盖记录保留继承。脚本仅执行一次，不重复执行 ADD COLUMN。

索引新增 `(user_id, parent_id)`、`(user_id, template_id)`。层级、路径和子节点不冗余存储。

## 接口

- `GET /api/timeTrackerCategory/list`：合并个人覆盖后，返回可用于新建记录的分类（排除停用父级的子级）。
- `GET /api/timeTrackerCategory/all`：当前用户完整分类元数据，包含停用分类，供历史显示、筛选与统计使用；不会返回其他用户的私有分类。
- `GET /api/timeTrackerCategory/hidden`：用户独立隐藏的分类，包含个人原创分类，可恢复。
- 新增/编辑接口增加 `parentId`。省略表示不修改；公共分类覆盖显式传 `null` 表示恢复继承；`"0"` 表示根级。原创分类显式传 `null` 规范化为 `0`。响应 ID 仍为字符串。
- 管理员变更公共树时同步校验个人有效树，拒绝导致任一用户出现第三级的操作。层级变更在事务内按主键顺序锁定分类行后校验，避免并发新增/移动绕过深度限制。
- 新建时迹或更换分类必须使用有效分类；编辑历史记录时允许保留原来的停用分类。

## 页面与兼容

我的分类和公共分类管理采用两级缩进、展开/收起、一级行新增子分类按钮；编辑弹窗只允许选择一级作为上级。个人覆盖支持恢复公共归属。拖拽只改变同级排序，改变归属通过编辑弹窗完成。

录入分类支持完整路径搜索，一级仍可直接选择。运动子分类沿用上级的运动明细行为，阅读/观影关联类型匹配也检查完整路径。这部分仍兼容原有按名称识别业务的实现，未另增业务类型字段。

时迹主页面、看板、首页饼图及各分类图表统一使用两级关系。时间类型图表仍按实际记录分类的 `time_type` 统计。Jev 和 MCP 分类名称包含上级路径，分类 ID 契约不变。
