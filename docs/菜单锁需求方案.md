# 菜单二级锁

二级锁用于在账号已登录后，对用户选定的敏感菜单再次验证密码。它与密码库的解密主密码是两套能力，不互相替代。以下按当前后端与 Web 实现说明，移动端沿用同一后端权限规则。

## 配置与访问

1. 在「个人中心 → 二级密码」设置密码；已有密码时，修改需要验证旧密码。
2. 选择需要保护的菜单并保存。菜单锁按用户配置；保存锁列表时校验二级密码，不把勾选状态直接当作授权。
3. 访问受保护菜单时显示居中验证弹窗；取消返回，不能通过关闭遮罩绕过。
4. HTTP 接口同样受拦截。需要解锁时后端返回整数业务码 `2001` 与 `data.menuPath`；HTTP 200 仍可能是拒绝结果。

二级锁配置与菜单匹配以数据库权威状态为准。管理员角色、菜单启用状态和业务数据归属校验仍然生效，二级锁不授予原本没有的权限。

## 有效期与失败限制

- Redis 按“用户 + 锁定菜单路径”保存解锁状态，固定有效期 **30 分钟**；当前实现不会因普通访问自动续期，不能表述为“连续无操作 30 分钟才上锁”。
- 一次验证会解锁匹配的当前菜单及其父级锁，不是严格的一次只解锁一个节点。
- Web 解锁标记保存在内存，页面刷新后前端标记会清空；这不等于 Redis 授权被删除。再次进入时由客户端交互与后端校验共同处理。
- 连续 5 次密码错误后限制验证 10 分钟；正确验证清除失败计数。限制为用户级，不允许换菜单绕过。
- 旧请求、旧定时器或账号切换后的结果不能继续授予当前页面权限。

## 忘记密码

通过当前绑定邮箱发送验证码，校验后设置新二级密码。验证码有效期为 5 分钟，邮件发送保留单 IP、单邮箱及全局频率限制。错误与失败不得清空用户尚未提交的表单。
