# 菜单锁需求方案

## 背景

用户有个人的敏感菜单（如密码管理、财务记录），希望进入这些菜单时额外验证一次密码，即使主账号已登录。菜单锁是用户级的 —— 每个用户自行决定锁哪些菜单。

## 核心逻辑

1. 用户在「个人中心 → 二级密码」设置二级密码
2. 用户在「个人中心 → 二级密码」勾选需要加锁的菜单
3. 访问被加锁的菜单时，弹出密码验证弹窗（居中）
4. 验证通过后，30 分钟内免密访问该菜单
5. 忘记二级密码时，通过绑定邮箱的验证码重置
6. 直接调用接口同样被拦截

---

## 功能清单

### 1. 二级密码设置

- 入口：个人中心 → 二级密码
- 首次设置：输入密码 + 确认密码
- 修改密码：输入旧密码 + 新密码 + 确认密码
- 密码复杂度不做限制

### 2. 菜单锁选择

- 入口：个人中心 → 二级密码 → 菜单锁区块
- 展示当前用户可见的所有菜单，每项带复选框，父子菜单缩进显示
- 勾选的菜单即被加锁，保存后立即生效
- 侧边栏中已加锁的菜单项旁显示锁图标

### 3. 菜单访问拦截

- 前端路由层面：点击加锁菜单时弹出验证弹窗，必须输入密码或取消后退回
- 后端接口层面：请求到达时，若对应菜单已被用户加锁且未解锁，返回特定错误码
- 弹窗居中、不可关闭（无 X 按钮、无 ESC、无遮罩关闭）

### 4. 解锁状态

- 一次解锁一个菜单
- 有效期 30 分钟无操作自动锁定
- 页面刷新后解锁状态丢失，需重新验证
- 连续 5 次密码错误，锁定 10 分钟

### 5. 忘记二级密码

- 已设置二级密码的用户，设置页出现「忘记二级密码？」入口
- 展示当前绑定邮箱，点击发送验证码
- 输入验证码 + 新密码即可重置
- 验证码 5 分钟有效，有发送频率限制

---

## 边界情况

- 未设置二级密码时，菜单锁功能可配置但不触发拦截
- 修改/清除二级密码后，锁列表不受影响
- 管理员禁用某菜单后，用户对其的锁标记自动失效（后端查询时过滤已禁用菜单）
