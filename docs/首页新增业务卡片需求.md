# 首页新增业务卡片需求

首页新增目标、纪念日、阅读、会员、观影五张卡片，支持快速查看和编辑。Web、移动端及微信小程序采用一致的数据规则。

共同卡片目录、配置、刷新与生命周期见 [首页功能说明](首页功能说明.md)，实现差异见 [首页卡片核查与补齐清单](mobile-migration/home-card-audit.md)。本文描述业务需求，不代表两端每项交互已经实现。

## 展示范围

| 卡片 | 数据来源 | 首页展示内容 |
| --- | --- | --- |
| 目标 | 用户手动固定的目标 | 标题、状态、当前值与目标值、截止日期；进度沿用目标模块计算规则，不新增独立百分比字段 |
| 纪念日 | 用户手动固定的纪念日 | 图标、标题、日期，以及“还有 N 天”“已经 N 天”或“就是今天” |
| 阅读 | 自动展示全部“想读”和“在读”的阅读记录 | 小封面、标题和想读／在读状态，不展示进度 |
| 会员 | 自动展示当前用户尚未过期的会员，包括生效中和即将到期 | 图标、名称、到期日、剩余天数；自动续费状态用图标表示 |
| 观影 | 自动展示全部“想看”和“在看”的观影记录 | 小海报、标题和想看／在看状态，不展示进度 |

阅读对应阅读记录中的书籍、文章等内容；观影对应观影记录中的电影、剧集等作品。微信读书和视频观看不纳入本期这两张卡片。

## 固定与状态变化

目标、纪念日沿用闪念的固定方式：

- 业务列表提供图钉按钮，点击固定或取消固定；新增、编辑弹窗提供“添加到首页”开关，随保存提交。
- 首页条目操作菜单支持取消固定，只移出首页，不删除原记录。
- 从首页新增目标、纪念日时默认开启“添加到首页”，允许关闭。
- 固定关系保存到服务端，跨端同步；默认新固定的排在前面，支持调整顺序，编辑内容不改变固定顺序。
- 目标完成、搁置、超期后仍保留；纪念日经过目标日期后继续显示已经过去的天数。取消固定或删除原记录后移除。
- 纪念日沿用原始日期计算，本期不增加每年重复、农历或自动跳到下一年的规则。

阅读、观影、会员不增加固定开关：

- 阅读按“在读、想读”、观影按“在看、想看”分组排序，同状态内沿用业务列表顺序；不受业务页面临时筛选条件影响。
- 阅读改为读完或搁置、观影改为看完或搁置后，自动移出首页；改回符合条件的状态后自动出现。
- 会员排除已过期记录，按到期日由近到远排序，同日按记录 ID 稳定排序；今天到期仍视为有效，与会员模块一致。
- 会员过期后从首页隐藏，更新到期日期后同步刷新；自动续费标记不触发自动延长日期。
- “全部”表示所有符合范围的记录均可查看，不截取固定数量后丢弃其余记录。

## 数据结构与接口

仅 `goal`、`anniversary_record` 新增下列字段，沿用闪念 `is_pinned` 的命名；本期不改闪念表，不新增首页数据表。

| 字段 | 类型与默认值 | 规则 |
| --- | --- | --- |
| `is_pinned` | `TINYINT NOT NULL DEFAULT 0` | `0` 未固定，`1` 固定到首页 |
| `pinned_sort` | `INT NOT NULL DEFAULT 0` | 固定条目的顺序，数值越小越靠前；取消固定归零 |

- 配套索引为 `(user_id, is_deleted, is_pinned, pinned_sort, id)`；固定查询按 `pinned_sort ASC, id DESC`，不受目标状态影响。
- 创建、编辑请求支持可选 `isPinned`，未传时保留原状态；响应增加 `isPinned`、`pinnedSort`。排序值由服务端管理，不通过普通编辑直接赋值。
- `GET /goals?isPinned=1`、`GET /anniversaryRecords?isPinned=1` 返回当前用户的固定记录。
- `PUT /goals/{id}/pin`、`PUT /anniversaryRecords/{id}/pin` 接收 `{isPinned: 0或1}`，返回更新后的记录。
- `PUT /goals/pinned-order`、`PUT /anniversaryRecords/pinned-order` 接收 `{ids: string[]}`，按数组顺序保存当前全部固定记录；记录集合已变化时拒绝旧排序，客户端刷新后重试。
- 固定、取消及排序校验当前用户归属，并在事务内处理；ID 全程使用字符串。新固定放最前，重复固定不改变顺序。
- 阅读、观影复用分页查询的 `activeOnly=true`、`inProgressFirst=true`，会员复用全量列表；三类不新增固定字段。
- 最大高度由客户端统一配置，不存入业务表。数据库提供新库完整结构及旧库增量迁移，升级后再启用依赖新字段的服务。

## 卡片高度与交互

- 五张卡片使用紧凑列表。Web 多列布局与原有首页卡片等高：平板双列为 250px，桌面三列为 280px；不因条目较少缩短卡片。手机单列及移动客户端仍按内容自适应，避免少量数据撑出大块空白。
- 本期默认卡片整体最大高度为 **280px**，包含标题、内边距和列表；Web 使用 CSS px，移动端采用等效逻辑像素。该值属于本期设计默认值，统一管理。
- 超过最大高度时，标题栏固定，仅卡片内容区纵向滚动；不通过展开无限增高卡片，不横向滚动。
- 若接口分页，滚动到卡片内容底部自动加载下一页；移动端自有 `scroll-view` 使用 `scrolltolower`。不增加“加载更多”按钮。
- 分页请求去重，末页或空页停止；失败保留已加载数据与页码，在底部重试失败页。刷新、筛选或离页后的旧响应不得覆盖新状态。
- 标题最多两行，超出省略；封面、海报使用统一小尺寸，失败时显示占位，不改变条目高度。图标操作保留可访问名称和足够的点击区域。
- 点击卡片标题进入业务列表，点击条目打开原记录编辑弹窗；Web 在首页直接编辑，移动端可进入对应业务页后自动打开原编辑弹窗。右上角仅在支持新增时展示新增图标，不展示刷新按钮；Web 点击卡片顶部空白区域刷新当前卡片，加载中保留局部反馈且禁止重复触发。标题跳转、新增及其他操作不触发刷新，空白刷新区域支持键盘操作。移动端整页刷新遵循下拉规范，同时应支持卡片顶部空白局部刷新，不常驻刷新图标按钮，当前两端均已提供该入口。阅读和观影新增时沿用原表单状态规则，保存后仅符合展示条件的记录进入首页。
- 卡片标题复用对应菜单的图标与颜色，不另设独立图标；Web 阅读采用“在读、想读”两排横向书架：状态位于每排左侧，竖排文字与封面垂直居中，不展示状态圆点；右侧仅展示 2:3 封面，桌面及手机为 66×99px，平板短卡为 56×84px，让两排充分利用卡片高度，封面间距 12px，不显示书名；无书籍的状态整排隐藏；两排独立左右滚动，超出范围时露出右侧下一本，按状态分别查询，横向接近末尾继续分页。观影采用 A 版紧凑列表：左侧统一 2:3 小封面，右侧最多两行标题及状态，不显示进度；按卡片自身宽度自适应排版，宽度达到 380px 时双列，较窄卡片单列；封面为 32×48px，条目高度 64px，同等高度下宽卡可完整展示 6 条，多行内容在卡内纵向滚动，骨架屏沿用相同布局。会员保留现有列表样式，不使用方案图中的品牌图标；日期与剩余天数分列显示。
- 进度、日期、状态编辑成功后更新对应卡片；删除原记录后移除对应条目。

## 加载与权限

- 首次加载显示与列表条目匹配的低对比骨架占位，不叠加顶部蓝线或转圈；加载成功且无符合条件的数据时隐藏卡片，首次固定或新增符合条件的数据后显示。
- 请求失败显示卡片内重试入口，不把错误视为空数据；已有数据时保留内容，刷新不清空列表，仅标题栏显示轻量三点状态；分页加载在列表底部追加一条骨架，不覆盖已有内容。
- 仅查询当前用户有权访问的数据，遵守所属模块权限和二级锁；未解锁时不展示业务内容，服务端执行相同校验。

## 验收要点

- 目标、纪念日固定与取消固定有效，刷新及跨端登录后保持一致；业务状态变化不会自动取消固定。
- 阅读仅有想读、在读，观影仅有想看、在看；会员仅显示未过期记录，状态变更及时反映到首页。
- 手机、平板、桌面及深浅主题下，Web 多列卡片底边对齐，单列少量数据紧凑，大量数据不超过最大高度；标题栏稳定，卡片滚动与整页滚动可正常切换。
- 大量数据可滚动查看完整范围；分页去重、末页停止、失败恢复有效，长标题和封面异常不撑高卡片。
- 无数据、加载失败、原记录删除、权限受限和二级锁场景符合上述规则。

- Mobile 阅读卡片采用两排横向书架：上排在读、下排想读，左侧竖排状态使用统一排版的 body 角色及 label 行高（配置以 `src/styles/typography.json` 为准）；封面 66×99px，仅展示图片，每排独立横滑。空分组隐藏，向右接近末尾继续加载，分页失败在书架末尾重试，点击封面沿用首页编辑弹窗。
